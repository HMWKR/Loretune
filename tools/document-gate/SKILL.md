# 문서 완료 검사

문서 작성·수정 작업의 시작과 최종 보고 전에 이 폴더의 `check.py --root <작업 디렉터리>`를 기존 Python 3로 실행한다. 설치나 외부 호출이 없다. JSON 결과와 종료코드가 검증 근거다. 현재 프로젝트 지침과 실제 사용자 승인이 우선한다.

- 정책은 가장 가까운 `.document-gate.json`이다. 중첩 Git/worktree 경계를 넘어 상위 정책을 물려받지 않는다. 프로젝트마다 경로·등록부·분류·문맥 기준을 선언하며 임의 명령은 받지 않는다.
- `not-configured`(2)는 정상 검증 통과가 아니다. 필요한 정책만 제안하고 승인 없이 새 registry나 온톨로지를 만들지 않는다. 프로젝트 간 설정을 복사해 자동 적용하지 않는다.
- `blocked`/`review-required`(1)는 등록 누락, 분류 미결정, 해시 불일치 또는 문맥 재검토다. 등록·승격·문맥 재생성은 별도 검토·권한이 필요하다. 검사 통과를 위해 역사 문서를 현행으로 승격하거나 hash만 덮어쓰지 않는다.
- 문서 `legacy-review-pending`과 문맥 `review-required`는 해시·revision이 일치해도 미완료다. 역할을 명시적으로 검토·해소하기 전에는 통과로 보고하지 않는다.
- `invalid`(3)는 경로·정책·입력 안정성 검증 실패다. 비밀 파일·symlink·외부 경로를 우회해 읽지 않는다. 검사 자체를 못 했다고 보고한다.
- 검사기는 일반 파일만 읽는다. FIFO/장치/디렉터리와 잘못된 registry·receipt 구조는 원문 없는 실패로 반환한다. 파일 크기·문서 수 제한은 전체 파일시스템 응답 시간의 보장이 아니다.
- `pass`(0)는 선언된 문서 범위의 기계적 정합성이다. 의미 정확성, 제품 구현, 실사용자 검증, 런타임 IP 온톨로지 완성을 뜻하지 않는다.
- 결과의 범위·제외·미결정과 evidence hash를 최종 보고에 포함한다. 변경 이후 다시 검사해 그 시점의 결과를 사용한다. 검사기는 stdout 외 파일을 쓰지 않는다.

전역 AGENTS와 이 스킬은 실행을 안내하는 지침이다. 자동 실행을 보장하지 않는다. 지원되는 Codex Stop 어댑터는 `check.py --hook`이며 별도 신뢰 검토 후만 연결한다. transcript/assistant 원문을 읽거나 보관하지 않는다. Stop은 한 번의 후속 점검을 요청할 뿐 절대적 CI 차단이 아니다. `stop_hook_active`에서는 무한 반복 대신 미완료를 알린다. 보안·훅 신뢰 설정을 우회하지 않는다.

Stop에서 미설정·처리된 검사 오류·재진입은 안내만 반환한다. 최초의 정상 미완료 결과만 계속 실행을 요청하며, 추가 Codex 턴과 사용량이 생길 수 있다. native 활성화 전 정확한 명령·검사기 해시·전역 적용 범위와 기존 훅 차이를 검토하고 사용자의 확인 및 공식 신뢰 절차를 거친다. 훅 정의의 신뢰가 외부 검사기 파일 내용을 고정한다는 보장은 없으므로 검사기 변경도 재검토한다. 현재 후보는 미활성 상태다.

현재 지원 정책의 예는 프로젝트의 `.document-gate.json`이며 정책 없는 곳에 이 프로젝트의 규칙을 강제로 적용하지 않는다. 검사기를 CI/기존 pre-commit에 연결하려면 사용자가 지정한 프로젝트에서 기존 검사를 보존하여 명시적으로 연결한다. 전역 `core.hooksPath`를 변경하지 않는다.
