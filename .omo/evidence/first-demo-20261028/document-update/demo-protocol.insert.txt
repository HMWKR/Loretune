## 실동작·녹화 검증 계약 · DEMO-01 · 사용자 요청 1–7

다음은 기능 완료를 판정할 필수 증거다. 기존에 유효한 조사/실행은 재사용하고 변경된 소스·흐름만 다시 확인한다. 계획·테스트 수·화면 성공 표시만으로 완료하지 않는다. 합의된 요구를 제외하거나 제품 방향을 바꿀 필요가 있으면 그 부분만 질문하고 독립 작업은 계속한다.

|사용자 요청 단계|검증·전달 기준|
|---|---|
|1. 최신 상태·시연 범위|대화 요구·최신 유지 문서·설계/아키텍처·계획·잔여·검증 기록과 실제 코드를 대조. 음악 단독과 선택적 사진 경로를 모두 유지하며 사진/3D는 필수 아님. 사용자 과업→화면/조작→API/모듈/저장 상태→기대→방법/결과→증거/녹화 타임코드→완료·실패·미검증·승인 대기를 추적. 최신 사용자 자료·원본·이전 산출물을 보존하고 문서 등록/승격/생성문맥은 승인 범위 내에서만 처리|
|2. 내부 시스템|실제 UI 조작→API 요청→입력·권한·권리·비용·승인 검사→내부 작업/모델 실행→작업 상태·산출물 저장→상태 재조회→화면 preview→편집·최종 출력·다운로드를 연결. 선택 모델/실행 모델 일치, 전달된 현재 음원·장면·편집 버전·지원 도구와 실제 적용 결과를 확인|
|3. AI 영상 모델 전 제작 완주|빈 프로젝트 음악 단독→사진 선택 추가→독립 타이포/모션 생성·플랫폼 preview→문구·크기·색·위치·표시 시간·움직임 등 실제 지원 속성 수정→원본 저장·재생성 반영→후보 비교·Take 선택·검토/필요 승인→타임라인 배치·순서/길이·음원 구간·자막 편집→출력·플랫폼 재생·다운로드→재열기 이어쓰기. 기존 이미지/영상 위 타이포 겹치기·위치/시간 수정도 실제 결과로 확인|
|4. 디자인·조작|설치된 Karpathy/Hallmark/Impeccable과 필요한 기능 검증 스킬의 실제 지원 지침을 사용. 스킬 읽기·명령 실행·수동 검토·실제 결과를 구분. 내부 ID/진단은 기본 화면에서 줄이고 비용·권리·승인·오류·복구는 필요한 시점에 제공. 중복 입력/단계 병합을 검토하되 중요한 사용자 결정을 임의 자동화하지 않음. preview/편집 반영·로딩/실패/완료·키보드/포커스 확인|
|5. 1차 실제 화면 녹화·사용자 검토|설치·지원되는 녹화 도구로 실제 플랫폼 조작을 녹화하고 녹화본 자체의 재생/내용을 확인. 시작 조건·입력, 타이포 생성/수정/배치와 실제 전후 차이, 음원/장면/자막 편집, 승인·출력 진행/완료, 플랫폼 재생·다운로드·재열기, 중요한 오류·복구를 보여 줌. 연속 정상 흐름을 우선하고 편집/배속/생략·실패·수동 개입·무음 여부를 공개. 녹화 전 키/개인정보 노출 방지. 녹화본·타임코드·실제 출력·요구별 검증·내부 설계 일치/차이·남은 실패/미검증/제약을 전달|
|6. 명시 승인 후 실제 AI 뮤직비디오|1차 녹화 검토/승인은 무제한 비용 승인이 아님. 호출 전에 사용할 모델·전송 자료·길이/규격·호출 횟수·최대 비용·보관 조건·실패 시 비용 처리를 제시하고 해당 범위 승인 후 호출. 음원/선택적 사진→기획/장면→실제 영상 생성→수신/플랫폼 저장/preview→후보 검토/선택→수정/재생성→타이포/음원/자막 편집→승인→최종 출력/재생/다운로드/재열기를 플랫폼에서 완주|
|7. 최종 뮤직비디오·2차 녹화|실제 AI 요청→수신→편집→최종 출력의 플랫폼 조작을 다시 녹화. 완성 뮤직비디오·2차 녹화본·편집/배속 여부·타임코드, 모델/입력/생성 결과/편집 버전/최종 산출물 연결, 관측 사용량·확정 청구 상태, 남은 제한/실패/미검증을 전달. 내부 검증 기록은 일반 사용자 화면과 분리. 시연 성공과 플랫폼 출시 준비 완료는 별도로 판정|

내부 검증의 공통 반례:

- AI 설명과 실제 편집 결과, 제안·preview·사람 승인·실제 적용·최종 출력 승인을 각각 비교한다. 승인 후 입력/원본/편집 버전이 달라지면 오래된 실행을 차단한다.
- 대화별 이력·초안·모델 선택 격리, 공유 자산·타임라인 충돌과 공통 예산 제한을 실제 요청/저장 상태로 확인한다.
- 취소·타임아웃·재접속·서버 재시작·결과 미확정에서 요청 ID·작업 ID·버전·상태 전이·원장/예약/관측 사용량을 연결한다. 중복 실행·비용 누락·확인 없는 자동 재호출/무제한 재시도를 막고, 실패/취소/미확정의 기존 상태와 비용부터 조회한다.
- 저장 산출물 SHA와 실제 다운로드 바이트, 실제 decode/플랫폼 재생·자막·재열기 후 원본 구성·편집·출력 유지를 대조한다. 로그와 내부 식별자는 증거에 남기되 기본 작업 화면에 불필요하게 노출하지 않는다.
- 합성 공급자 응답·로컬 HTTP·실제 내부 렌더·실제 모델 호출·관측 사용량·확정 청구는 별개다. 실제 사용자가 참여하지 않은 검증을 사용자 시험으로 부르지 않는다.

편집 가능한 타이포/모션 원본과 완성 MP4 클립 편집을 구분한다. 드래그·다중 레이어는 실제 지원 범위만 설명하고, UI가 없는 합성·저장 기능을 별도 앱이나 수동 스크립트로 대신해 성공으로 보고하지 않는다. 개발 서버가 로컬이어도 사용자는 플랫폼 UI 안에서 완료해야 하며 플랫폼이 관리하는 내부 렌더 엔진은 사용할 수 있다. 기존 음원·사진·후보·승인본·출력은 정상/오류/복구 흐름 전체에서 보존한다.

**승인 대기 경계:** 1차 녹화본을 사용자가 검토하고 다음 단계 진행을 명시 승인하기 전 실제 AI 영상 모델을 호출하지 않는다. 무응답은 승인이 아니다. 실제 Claude는 승인된 모델·전송 자료·예산을 별도로 확인한다. 실제 호출이 없으면 합성 검증으로 남긴다. 요구별 실제 결과·잔여·이번 시연 종료 근거를 설명할 수 있어야 하며, 미검증·권한 대기를 완료로 바꾸지 않는다.
