## 제품 내 에이전트 작업 공간을 개선할 때

- 최신 사용자 정정은 이전 문구의 같은 대상·범위에 우선한다. 요구→현재 기능/공백→담당→실제 합격 증거를 기존 기록에 연결하고, 문서 담당은 제품 구현과 겹치지 않는 파일에서 병렬로 갱신한다. 구현 중 항목은 완료로 쓰지 않는다.
- 공통 패널의 모든 작업창 접근·너비·모델/대화·초안·포커스 유지와, 내부 도구의 실제 실행 능력을 따로 검증한다. 같은 UI를 복제해 별도 문맥이나 숨은 저장 상태를 만들지 않는다.
- permission·추론 강도는 공급자/모델과 실제 도구 계약에 맞춘다. 표시 옵션·서버 실효값·전송 본문·요청 중 변경·재열기의 일치를 확인하고 미지원 값을 자동 대체하지 않는다.
- 제품 에이전트의 Full Access를 포괄적 결제·자료 전송·권리·삭제 승인으로 해석하지 않는다. Loretune의 확정 정책은 **계정 삭제 항상 금지, 파일 등 다른 삭제는 대상·영향을 제시한 해당 삭제의 사용자 명시 허용 필요**다. 서버에서 검사하고 오래된 허용을 다른 대상/버전에 재사용하지 않는다.
- 현재 영상·추천 자산·작업 현황은 모델이 실제로 조회한 근거와 연결한다. metadata만 받은 상태를 영상/음원 내용을 직접 관찰했다고 쓰지 않는다. 참여자/권한 데이터가 없다면 엔진 worker나 대화를 협업자로 표시하지 않는다.
- 녹화 시연의 완료 증거는 실제 플랫폼 조작 녹화본 자체의 재생/내용 확인, 타임코드·생략/배속/무음 공개, 실제 출력·내부 실행·재열기 연결이다. 시연 성공과 출시 준비 완료는 별도로 판단한다.
