From Tripo to UE5: Make a Generated Character Walk

“

From a character reference to a playable character in UE5, follow a creator’s five-stage workflow with Tripo, Blender, and GPT-6 Astra. See how modeling, materials, rigging, animation, and UE5 retargeting come together—and what needed fixing before the character could finally walk.

Can’t get your character to walk? The model is done, but it just stands there.

Bring it into UE5 and see if it can take a first step. So I asked my best employee, GPT-6 Astra, to teach it how to walk in UE5.

I first used Tripo to generate a 3D model from character reference images. With GPT-6 Astra’s help, I then completed the material, rigging, animation, and export workflow in Blender. After importing the character into UE5, I continued with skeletal retargeting and input mapping. In the end, a character that had previously existed only in a reference image finally took its first step inside UE5.

I divided the entire process into five stages. For each stage below, I note what I did, what GPT-6 Astra solved, and what I actually got.

What Did My “Employees” Do?

Tripo: Creating the Character from Reference Images

Tripo was responsible for turning the character in my reference images into a 3D model. It generated the character’s body, clothing, shoes, hair, and high-poly hand models. It also produced reasonably clean topology and used Smart UV to generate UVs that were more suitable for later production work.

GPT-6 Astra: Taking the Character All the Way to UE5

GPT-6 Astra helped me take the character from Blender into UE5. It helped plan the entire workflow and organize my development log. I followed the stages it suggested and worked through them one by one.

In Blender, it helped me choose a suitable Rigify sample and build a Meta-Rig that matched the character’s proportions. It also created an Idle animation based on an animated reference. After that, it helped me develop a bridge plugin for Blender and UE5. The plugin handled character rigging and export in one click, saving me from repeatedly exporting and importing files by hand.

Once the character was in UE5, GPT-6 Astra continued to guide me through skeletal retargeting. It also helped me build a character-control system based on UE5’s Enhanced Input System, allowing the player to control the character’s movement. I’m still a beginner when it comes to UE5, so I often felt completely lost during the process. Whenever that happened, GPT-6 Astra helped me sort out the problem and decide what to do next.

Stage One: Separating the Reference Image and Generating the Model with Tripo

Before you can put the clothes on, you have to take them off. No character is an exception. I began by separating the complete character image into different parts:

  • A Base Mesh without hair
  • Clothing
  • Pants
  • Shoes
  • Hair
  • Hands, if more detailed hand geometry was needed

If you need more detailed hands, you can create a separate reference image for one hand and use it as input for Tripo.

The eyeballs do not necessarily need to be separated into their own reference image. The newly released official version of Tripo P2 is now very good at recognizing the teeth, tongue, and eyeballs inside a character’s head. It can also generate these parts with their own topology. However, there is one thing to watch out for. Because these components are hidden inside the head, it is easy to overlook their material assignments. Based on my own tests, you should check their materials before exporting. Otherwise, they may cause unexpected problems after the model is imported into UE5.

Some AI image-generation models do not allow users to generate nude characters. In that case, you can use an image of the clothed character and ask the model to reconstruct the Base Mesh underneath the clothing—the basic gray body model.

Different Parts Require Different Reference Images

Base Mesh. I generated the Base Mesh in Tripo using the P2 model. For this workflow, I aimed for approximately 10,000–15,000 quad faces.

Hands. For a single hand, I aimed for approximately 2,500–3,000 quad faces. When creating the reference image, try to keep all five fingers as separate as possible. This usually leads to better results when generating a three-view model.

Shoes. Shoes often have relatively complex structures and contain multiple small, separate components. For this reason, three-view references usually work better.

Pants and Clothing. These models are generally less complex, so a single-view reference is often enough to achieve a good result.

Hair. Hair often contains hollow or cut-out sections, so three-view references are recommended.

The official version of Tripo P2 also introduced another very useful feature. If you are not satisfied with a particular part of the model, you no longer have to regenerate the entire model. Simply select the area you want to change, and Tripo will regenerate only that region.

Because I planned to add PBR textures to the clothing later, I first needed a clean and well-organized UV layout. This is where Tripo’s Smart UV feature became particularly useful. Previously, models generated with textures directly in Tripo often came with somewhat messy UV layouts. The new Smart UV feature has made a significant improvement.

To compare the results, I created a side-by-side example. The left side of the video shows the UV layout generated by an earlier version of Tripo, while the right side shows the UV layout generated with the new Smart UV feature.

If you plan to use tileable textures, a UV layout like the one on the left is practically unusable. The Smart UV layout on the right, however, is much more suitable for this type of texturing. This was a very useful update from Tripo.

After generating all the parts, I downloaded the models as FBX files and imported them into Blender for further processing. Once I assembled the separate meshes, I used the Grab brush in Sculpt Mode to make small adjustments. Even minor changes could make a surprisingly big difference. For the hand details, I exported the high-poly and low-poly versions separately and then baked the normal maps in Marmoset Toolbag.

At this point, the model was finally ready—but it was still just a collection of gray meshes waiting to be processed. The next step was to give the character proper materials.

Stage Two: Creating Materials with GPT-6 Astra and Blender MCP

I provided GPT-6 Astra with several material reference images and asked it to recreate the materials in Blender. For the skin material, I specifically asked GPT-6 Astra to keep the node setup compatible with Blender’s Texture Paint mode. This allowed me to add more details manually later, such as freckles on the character’s face. GPT-6 Astra also generated the black-and-white mask used to control the freckles. GPT-6 Astra helped me create the materials for the character’s eyes, skin, and shoes. By using MCP to control Blender, I only needed to describe the visual result I wanted. GPT-6 Astra handled the node setup and parameter adjustments.

Once the materials were finished, the character finally looked like a complete character. However, it could still only stand in one place. The next step was to give it a skeleton and make it move.

Stage Three: Rigging and Animation with GPT-6 Astra

For this workflow, I used the Rigify rigging system. I first asked GPT-6 Astra whether it knew how to use the Rigify add-on. It answered with complete confidence: yes. I then asked it to choose a suitable Rigify sample based on the character’s proportions and build a reasonable Meta-Rig. Once the Meta-Rig was created, I only needed to enter Edit Mode, make a few small adjustments to the bone positions, and click Generate Rig. The character’s rig was ready.

I also tried asking GPT-6 Astra to handle the skinning. However, the results were not particularly good. It seems that not every task should be handed directly to AI. For now, skinning is still better handled manually—which also gave my “employee” a chance to take a break. Fortunately, once the Base Mesh had been skinned, transferring the weights to the clothing, pants, shoes, and socks was a relatively standardized process. That made it a good task for GPT-6 Astra, and it improved the overall efficiency of the workflow.

Creating the Idle Animation

For the animation stage, I provided GPT-6 Astra with an animated reference of the character’s Idle motion. I also described the key movement details and set the animation to:

  • 24 frames per second
  • 48 frames in total
  • Looping playback

GPT-6 Astra did a good job creating the animation. After making a few minor adjustments to the animation curves, I had a fairly complete result.

At this point, Blender contained a complete character that could play an animation. However, Rigify’s skeleton is relatively complex. It includes several different types of bones, such as DEF, ORG, MCH, and CTRL bones. This structure is not suitable for direct use in UE5. Before exporting, I therefore needed to transfer the character and its animation to a simpler skeleton designed for use in a game engine.

For this step, I used the GameRigTools add-on. First, I generated a new skeleton with the same DEF-bone hierarchy as the original character rig and named it GameRig. I then transferred the character’s weights to the new skeleton. Next, I used constraints on GameRig to copy the transform data from the original rig. This allowed the existing animation to play correctly on GameRig. Once I confirmed that everything was working as expected, I baked the animation onto the GameRig skeleton. At this point, all I needed to do was export the character model and the GameRig skeleton.

My materials also contained procedural elements, so they were not made entirely from PBR texture maps. Before importing the character into UE5, I needed to bake those procedural materials into texture maps. Material baking is a fairly repetitive process. Since it was exactly the kind of mechanical task that could be delegated, I decided to leave it to GPT-6 Astra in the next stage. The next step was to organize the Blender assets into a format that UE5 could understand.

Stage Four: Building a Bridge Plugin with GPT-6 Astra

I first asked GPT-6 Astra to control Blender and UE5.7 through MCP and run through the entire character export and import workflow. GPT-6 Astra acted as a useful pathfinder. It tested the workflow first, helping me identify and resolve potential problems before I used it more extensively. Once the process had been tested from beginning to end, I had a much clearer and more reliable workflow to follow. Of course, the testing process also revealed several problems:

  1. Blender and UE5 use different unit systems. When the character was exported from Blender and imported into UE5, the root bone ended up with a scale that was 100 times too large.
  2. After baking the textures and rebuilding the materials in UE5, I found that some materials had been assigned to the wrong meshes. Further investigation revealed that the tongue and teeth were still inside the head but had not been assigned separate materials. As a result, they were exported into UE5 along with the head.

After GPT-6 Astra completed the workflow and fixed these problems, I checked the animation sequence in UE5 and confirmed that it passed the acceptance test. I then asked GPT-6 Astra to create a Blender plugin and a communication protocol between Blender and UE5 based on the tested workflow. The plugin uses a non-destructive workflow. It does not modify the procedural materials in Blender.

At this point, my character had finally moved from Blender into the world of UE5. However, entering UE5 did not mean that the character had learned how to walk. It had only arrived in its new environment. The final step was to let the player control it.

Stage Five: Retargeting the Skeleton in UE5 and Making the Character Walk

I’m still a beginner when it comes to UE5, and I did not fully understand how to retarget a Rigify skeleton after importing it into Unreal Engine. The tutorials I found online were either not detailed or systematic enough, or they required paid plugins. So I decided to ask GPT-6 Astra to become my teacher. First, I explained what I wanted to achieve:

  • Check the character skeleton currently imported into UE5.
  • Design a complete skeletal retargeting workflow.
  • Make sure the final character could directly use animation sequences from a UE5 template project.

Based on these requirements, GPT-6 Astra divided the entire process into the following stages:

As a beginner, I couldn’t understand this stage table at all. But that was fine. As long as GPT-6 Astra understood it, I only needed to understand whether each stage had passed its acceptance criteria.

I asked GPT-6 Astra to carry out the process one stage at a time. After each stage was completed and passed its acceptance test, I asked it to prepare a detailed, beginner-friendly guide to the practical steps involved. I then followed the instructions and completed the work step by step. Of course, it was also possible to use the results created by GPT-6 Astra directly without performing every step manually.

Thank you, GPT-6 Astra—my excellent employee. You did a great job, and you also made a great teacher. In the end, with GPT-6 Astra’s guidance, my character finally learned how to walk. This time, it was not simply imported into UE5. It actually took its first step under my control.

Frequently Asked Questions

Which parts of this workflow must be done manually, and which parts can be handled by AI?

Put simply, I made the decisions, and AI carried out the practical work based on those decisions. Most of the tasks I delegated to AI involved standardized procedures or repetitive operations.

Can the UVs generated by Smart UV be used directly for tileable textures? When is manual UV adjustment still necessary?

Based on my tests with this character, yes. The UVs generated with Smart UV worked very well with tileable textures. I plan to test the feature with more types of characters in the future.

However, if you want better material quality on areas that players may view up close—such as the head and hands—I still recommend adjusting the UV islands manually in Blender. Smart UV is already very capable, but it cannot completely eliminate texture-seam problems, especially with tileable materials. For this reason, I always import the UVs generated by Tripo into Blender and use a checkerboard texture to inspect the entire character. This makes it easier to spot any distracting or visibly distorted areas.

GPT-6 Astra only created a simple Idle animation. Could it also handle more difficult animations?

I have tried providing GPT-6 Astra with multiple static pose images and asking it to control the skeleton in Blender to reproduce those poses. This worked reasonably well. The final poses were generally similar to the references, and the overall compositions were also close.

This suggests that if a character animation can be broken down into a sequence of PNG images, those images might be usable as references for GPT-6 Astra. I am still testing how well it can handle more complex animations. For animations such as Idle motions, which involve relatively small movements, GPT-6 Astra is already capable of producing very good results.

Frequently Asked Questions

Which parts of this workflow must be done manually, and which parts can be handled by AI?

Put simply, I made the decisions, and AI carried out the practical work based on those decisions. Most of the tasks I delegated to AI involved standardized procedures or repetitive operations.

Can the UVs generated by Smart UV be used directly for tileable textures? When is manual UV adjustment still necessary?

Based on my tests with this character, yes. The UVs generated with Smart UV worked very well with tileable textures. I plan to test the feature with more types of characters in the future.

However, if you want better material quality on areas that players may view up close—such as the head and hands—I still recommend adjusting the UV islands manually in Blender. Smart UV is already very capable, but it cannot completely eliminate texture-seam problems, especially with tileable materials. For this reason, I always import the UVs generated by Tripo into Blender and use a checkerboard texture to inspect the entire character. This makes it easier to spot any distracting or visibly distorted areas.

GPT-6 Astra only created a simple Idle animation. Could it also handle more difficult animations?

I have tried providing GPT-6 Astra with multiple static pose images and asking it to control the skeleton in Blender to reproduce those poses. This worked reasonably well. The final poses were generally similar to the references, and the overall compositions were also close.

This suggests that if a character animation can be broken down into a sequence of PNG images, those images might be usable as references for GPT-6 Astra. I am still testing how well it can handle more complex animations. For animations such as Idle motions, which involve relatively small movements, GPT-6 Astra is already capable of producing very good results.
