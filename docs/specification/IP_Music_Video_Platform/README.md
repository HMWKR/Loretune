기준일: 2026-10-23. Aethon과 별도의 신규 사업·제품이다.

## 먼저 확인할 결론

사업화는 **조건부 검증을 진행할 만한 가설**이다. 현재 자료로 사업성·실제 영상 품질·유료 유지가 입증된 것은 아니다. 최초 고객은 같은 IP로 다음 8–12주 동안 서로 다른 제작 요청 3개 이상이 예정된 소규모 레이블·버추얼 그룹·반복 수주 영상팀으로 좁힌다.

핵심 가치는 이전 작품의 승인 설정·연출 선호·수정 이유를 다음 작품에 재사용해 설명과 재작업 부담을 줄이는 것이다. 공개 경쟁 기능에 이미 Story Bible·공유 자산·생성 편집이 있고 저가 MV 편집 상품도 있으므로 ‘최초 기억형’·‘항상 최저가’는 근거가 부족하다.

**네 가지 결정은 준비된 IP의 후속 초안 실행 전 목표다.** IP·곡·목적, 적용 설정·시점·예외, 콘티·규모·예산 승인, 실행을 뜻한다. 처음 자료 등록·출력 검토·수정·최종 승인까지 네 클릭에 완성한다는 의미가 아니다. 12개 업무와 네 가지 결정 묶음은 서로 다른 단위라 절감률을 계산하지 않는다.

## CLI 빠른 시작

전체 ZIP 또는 별도 CLI ZIP을 풀고 `project_kit` 폴더에서 실행한다. Python 3.11 이상과 표준라이브러리만 필요하다. 별도 API 키·DB·pip 설치는 필요하지 않다. Windows의 Python 명령이 다르면 `python`을 설치 환경의 `py -3.11` 등으로 바꾼다. 실제 실행 검증 환경은 Linux/Python 3.12이며 모든 운영체제의 별도 시험을 주장하지 않는다.

```sh
python kb.py validate --strict
python kb.py search "비용" --task business
python kb.py impact ASM-PRICE-001
python kb.py context --task business --out generated/context/business-my-task-001.md
python kb.py context --task product --out generated/context/product-my-task-001.md
python kb.py context --task pitch --out generated/context/pitch-my-task-001.md
python kb.py context-check generated/context/pitch-my-task-001.md
python cost_model.py --seconds 180 --mode hybrid --candidates 2 --monthly-outputs 4
```

배포본은 등록이 끝난 registry revision 3이다. 빈 키트용 초기 import를 반복할 필요가 없다. context 출력명은 작업마다 새로 정한다. 전체 문서를 무조건 넣지 않고 선택·생략 이유가 있는 receipt를 남기며, 실제 모델 토큰 수를 보장하는 토크나이저는 아니다.

## 파일이 많아졌을 때의 운영 규칙

현재 기준은 `registry/knowledge.json`의 `heads`가 결정한다. 수정 시각이나 파일명 `최종2`가 기준이 아니다. Source→Claim→Decision/Requirement→Screen/API/Test/Document의 연결을 명시한다. 문서 편집 승인, 사업 채택, 실험 검증 상태를 서로 분리한다.

동결 원문은 `sources/current_spec/`, 과거 문서는 `archive/v1/`에 있다. 새 초안은 `docs/`에 새 버전으로 작성하고 sidecar patch를 검토한 뒤 등록·승격한다. 변경은 dry run, 예상 registry revision, actor, 이유를 남긴다. 오래된 파일은 자동 삭제하지 않으며 기본 검색과 문맥에서 제외한다. 가격·모델·정책의 검토 기한을 넘기면 출처를 실제 다시 확인하고 새 버전을 만든다.

등록하지 않은 파일이나 선언하지 않은 관계까지 자동으로 이해하는 시스템은 아니다. 중요 비용·시장·성능 숫자는 Claim으로 연결한다. `cost_model.json`과 `cost_model.py`는 실행용 사본이며 이번 원가 주장의 근거는 `sources/current_spec/models/`의 동결 사본이다. 값을 바꾸어 새 주장을 만들 때는 새 config를 `docs/`에 두고 `--config`로 계산한 뒤 새 문서/가정/Claim 버전을 등록한다. 실행용 사본만 편집해서 승인된 원가 근거가 갱신된 것으로 취급하지 않는다.

검토 기한은 지나면 경고가 나도록 의도한 설계다. 경고를 없애기 위해 확인일을 자동 갱신하지 않는다. CLI의 로컬 actor는 인증된 전자서명이 아니며 Git과 사람의 검토를 대신하지 않는다. 프로젝트 지식 계층은 고객의 아이돌 설정·자산을 저장하는 제품 런타임 온톨로지와 별개다.

## 권장 첫 실행 범위

먼저 12–15팀의 최근 작업과 실제 지출을 확인하고, 3팀·각 3개 서로 다른 요청의 유료 파일럿을 준비한다. 30~60초의 리릭·자산 편집·단일 인물 짧은 생성부터 검증한다. 세 번째 요청에서의 사람 시간·선호·실패 원가를 같은 모델·자료·예산의 대조군과 비교한다. 3분 풀 MV·다인 군무·완전 자동화를 초기 출시 약속으로 잡지 않는다.

제안 목표는 온보딩 P50 20분, 반복 요청 초안 준비 P50 5분, 주요 결정 P50 4개, 초기 지원 샷 후보 3개 이내 채택률 80%, 단편 요청 수정 2회 이내 완료율 80%, ‘우리 IP답다’ 블라인드 중앙값 4/5, 세 번째 요청 사람 시간 중앙 상대 감소 30%다. 모두 달성 실적이 아니라 실험 목표다. 실패·중단·비용 상한 초과를 분모에서 빼지 않는다.
