# 7. 기존 제작 방식과의 공정 비교 및 사업계획·발표 문안

작성 기준일: 2026-10-23. 이 장은 Aethon과 별개의 신규 플랫폼에 대한 비교 설계다. 공식 제작자·공급자 페이지를 열람했으며 실제 주문, 경쟁 제품 실행, 우리 플랫폼 생성, 고객 성과 측정은 하지 않았다. **공개된 서비스 설명, 공급자의 마케팅 주장, 우리의 설계 목표, 향후 실측 결과를 구분한다.** 우리 금액은 제9장 원가모델 v2.0의 계산값을 사용하며, 실측 비용·확정 판매가격과 구분한다.

## 7.1 발표에 사용할 핵심 결론

지금 사용할 수 있는 중심 문장은 다음과 같다.

> 우리는 아이돌의 승인된 설정과 이전 수정 이유를 다음 제작에 연결하는 음악영상 제작 플랫폼을 설계하고 있다. 재사용 가능한 IP에서는 초안 실행 전 과정을 네 가지 주요 결정으로 구성하고, 결과 검토와 최종 승인은 별도로 남긴다. 반복 제작에서 사람의 준비·수정 시간과 최종 승인본당 총비용이 실제로 줄어드는지를 검증한다.

이 문장은 제품 방향과 검증 계획을 설명한다. 이미 구현됐거나 네 번이면 게시 가능한 MV가 완성된다는 뜻이 아니다. “세계 최초 지속기억”, “기존 제작 12단계가 4클릭으로”, “기존보다 몇 배 빠르고 몇 % 저렴”은 현재 증거로 사용할 수 없다.

공정 통합 자체도 새롭다고 단정하기 어렵다. 조사한 일본 제작 서비스는 일러스트부터 편집까지 일괄 의뢰를 제공하고, 한국의 AI 제작 대행도 기획·장면 생성·편집·싱크를 묶는다. Tunee와 Hedra는 곡 입력부터 영상 기획·생성·편집까지 연결된 흐름을 설명한다. Character App은 World의 설정과 변경 승인을 여러 작품에 연결한다고 설명한다. 따라서 차별화의 근거는 **통합 버튼의 존재보다, 아이돌 제작에서 검증된 수정 재발 감소·승인 통제·반복 제작 경제성**이어야 한다. [WF-S02, WF-S03, WF-S07, WF-S08, WF-S11]

## 7.2 ‘몇 단계’와 ‘몇 번’을 다섯 가지 단위로 구분한다

| 비교 단위 | 정의와 예시 | 무엇과 비교해야 하는가 | 현재 증거 상태 |
|---|---|---|---|
| 순차 작업·업무 단위 S | 콘셉트, 자산 준비, 장면 제작, 편집, 검토 등 제작 업무 | 같은 산출물의 같은 업무 목록 | 공개 사례와 분석용 분해는 가능. 시장 평균 없음 |
| 사용자 주요 결정 D | 적용 설정 선택, 콘티 승인, 지출 승인 등 결과를 바꾸는 판단 | 같은 시작·종료 지점의 결정과 반복 판단 | 우리 반복 요청의 초안 실행 전 4개 목표. 미측정 |
| UI 동작 U | 의미 있는 버튼·선택·업로드·확정 이벤트 | 같은 역할·기기·입력 조건의 이벤트 | 기존 06장의 8–12개 설계 예산. 실제 클릭 수 아님 |
| 생성 후보 G | 특정 장면을 새롭게 만들기 위한 창작 시도 | 같은 장면·모델·길이·선택 기준의 후보 | 비용 모델은 후보 2개, 1·3개 민감도. 실제 평균 아님 |
| 검토·수정 회차 R | 검토본을 확인하고 변경 목록을 묶어 다음 버전을 받는 한 회차 | 동일 수정 범위와 완료 기준의 검토 회차 | 초안 뒤 1–2회는 목표. 실제 성공률 없음 |

공급자 요청 수와 사용자 승인 수는 보조 지표로 따로 기록한다. 버튼 한 번이 여러 샷과 후보를 만들 수 있고, 배치 요청 한 건이 여러 산출물을 낼 수도 있다. 동일 요청의 네트워크 재전송은 새로운 창작 후보가 아니다. 반대로 후보를 만든 뒤 마음에 들지 않아 다른 지시로 다시 생성하면 새 후보다. 접수 여부가 불명확한 작업은 실패로 간주해 자동 재생성하지 않는다.

수정권이 두 번 포함됐다는 계약은 평균 두 번 만에 끝난다는 통계가 아니다. 고객 확인 지점 네 곳도 실제 네 회의 재작업이 발생했다는 뜻이 아니다. 모든 샷 후보가 평균 두 개라고 가정한 원가표는 사용자가 두 번 눌렀다는 뜻이 아니다.

### “기존 12 → 우리 4”에서 생기는 오류

12가 제작자 내부의 업무이고 4가 고객의 승인 묶음이라면 단위와 담당자가 모두 다르다. 기존 외주에서도 고객은 몇 번의 상담·검토만 하고 제작자는 많은 세부 작업을 할 수 있다. 우리 시스템 안에서도 검색·분석·생성·편집·검증 작업은 계속 존재한다. 따라서 이 숫자로 `(12−4)/12` 같은 절감률을 계산하지 않는다.

정직하게 바꾼 문구는 **“12개 제작 업무를 한 흐름에 연결하고, 반복 IP의 초안 실행 전 사용자 결정을 네 가지 묶음으로 설계”**다. 여기서 12는 이 문서가 비교를 위해 정한 업무 목록이며, 4는 미검증 UX 목표라고 같은 화면에 표시한다. 더 짧은 발표 문구는 **“기준 확인부터 초안 실행까지, 반복 제작을 네 가지 주요 결정으로”**이고, 바로 아래에 “재사용 가능한 IP 기준·최초 설정/결과 검토/최종 승인 별도·개발 목표”를 붙인다.

### 확인된 조건과 아직 가설인 문제를 분리한다

공개 조건에서 확인되는 것은 **중간 확인, 수정 범위 제한, 그림 원본과 상업 이용의 별도 조건, 제공 자료와 피드백 시점에 따른 일정 차이**다. 이로부터 후기 단계의 콘셉트 변경이나 자산 범위 불일치가 추가 협의를 요구할 수 있다고 추론할 수 있다. [WF-S02, WF-S03, WF-S04]

반면 “모든 제작자가 매번 아이돌을 처음부터 다시 설명받는다”, “기존 서비스는 서사를 기억하지 못한다”, “외주 수정의 대부분이 기억 오류다”는 이번 조사에서 확인되지 않았다. 기존 작업자도 장기 고객의 스타일 가이드와 과거 작업 파일을 재사용할 수 있다. 우리 인터뷰와 대조 실험은 이런 현실적인 기준선을 포함해야 한다. 우리 제품의 문제 가설은 **반복 설명과 기준 확인이 얼마나 발생하는지, 그중 구조화된 기억으로 줄일 수 있는 비중이 얼마인지**다.

## 7.4 현재 AI 도구의 공개 흐름과 우리와의 비교 경계

| 도구 | 공식 자료가 설명하는 방식 | 공개 항목 수가 의미하는 것 | 우리 발표에서 피해야 할 비교 |
|---|---|---|---|
| Tunee | 곡 업로드/선택 → 대화로 기획·생성 → 내장 편집으로 조정 | 공식 페이지는 연결된 경험을 설명하나 실제 조작 수를 제시하지 않음 | “경쟁사는 도구를 따로 써야 한다”, “우리만 곡에서 MV를 한 번에 만든다” |
| Hedra | 곡·브리프 → 콘티 → 인물·의상 등 기준 Elements → 짧은 클립과 동일성 검토 → Composer 편집·출력 | 공식 가이드의 5개 안내 항목. 각 항목 안에서 반복 작업 가능 | 완성 출력까지의 5항목을 우리의 초안 실행 전 4결정과 비교해 우위 주장 |
| LTX | 대본 → 모델·화면비 → 추출 Elements 검토·스토리보드 생성 | 스토리보드 시작까지의 3개 안내 항목 | “LTX는 3번이면 완성 MV”, 또는 우리 4보다 빠르다는 비교 |
| Character App | 지시·outline → 장면 이미지 → Take 생성·선택 → 조립; World/Bible과 변경 검토 | Director 문서의 번호에는 작성 팁이 섞여 있음. 별도 입문 가이드의 약 6개 결정·약 10분은 공급자 주장 | “경쟁사에는 승인된 기억이 없다”, “6 대 4이므로 33% 단축” |

근거: [WF-S07–WF-S12]. 네 도구 모두 이번 조사에서 앱을 직접 실행하지 않았다. 도움말은 기능 의도와 공개 사용법의 근거이며 실제 품질·가용성·재시도 비용의 실측 근거는 아니다. Character App도 기준과 참조가 시각적 동일성을 보장하지 않는다고 설명한다. 우리의 온톨로지 역시 모델의 얼굴·의상·동작 재현 능력을 대신 보장할 수 없다. [WF-S11]

**비교의 핵심은 기억의 유무 한 가지가 아니다.** 아이돌의 공식 설정·시대·이번 곡의 예외·권리 상태를 구별하는지, 승인된 이전 수정이 어느 장면에 적용됐는지 확인되는지, 좋은 장면을 고정한 채 잘못된 장면만 고칠 수 있는지, 그 결과 최종 승인본당 비용과 사람 시간이 줄었는지를 함께 평가한다. 이는 우리 제품의 설계·검증 항목이며 현재 확보한 경쟁 우위가 아니다.

## 7.5 같은 12개 업무에서 수동·자동·사람 승인을 비교한다

다음 W01–W12는 공급자의 마케팅 단계를 합산한 숫자가 아니라 **비교 실험을 위한 공통 업무 분해**다. 수동 경로도 기존 파일·템플릿·스타일 가이드를 사용할 수 있게 한다. ASSET 시나리오는 제공된 일러스트와 가사를 사용하므로 신규 그림 제작을 비교 비용에 끼워 넣지 않는다. 기존 제작이 이미 자동화하는 작업도 조사·실험에서 그대로 인정한다.

표의 자동은 구현 목표다. 권리·공식 설정·비용·최종 납품을 자동 승인한다는 뜻이 아니다.

| ID / 동일 업무 | 수동 또는 현재 도구에서 수행할 일 | 우리 첫 작품의 역할 분담 | 우리 후속 작품의 역할 분담 | 남는 사람 판단·종료 증거 |
|---|---|---|---|---|
| W01 산출물·범위 정의 | 곡·길이·화면비·용도·기한을 브리프로 정리 | 사람이 입력, 시스템이 누락 확인 | 기존 IP/프리셋을 제안하고 새 곡·목적 확인 | Producer가 범위 확정; 버전 있는 브리프 |
| W02 제공 원본·권리 확인 | 음원·가사·이미지의 출처·사용 범위를 확인 | 자료·증빙 등록, 시스템이 만료·누락 경고 | 기존 승인 범위와 현재 사용 조건을 대조 | IP 승인권자 또는 위임권자가 판단; 유효 권리 기록 |

| W07 기준 이미지·자산 준비 | 제공 일러스트의 선택·분리·크롭·배치, 필요 자산 확인 | 제공 자산 선택과 적합성 확인을 지원 | 승인된 의상·시대별 자산을 우선 제안 | 원본/파생본 계보. 신규 일러스트 외주는 별도 범위 |

| W11 검토·수정·최종 승인 | 검토자 의견 수집, 변경 범위 확인, 수정 후 승인 | 의견을 장면·버전에 연결; 선택 장면만 수정 제안 | 승인된 반복 교정을 확인하고 회귀 점검 | 권한 있는 사람이 새 버전 최종 승인. 새 비용은 재확인 |
| W12 납품·다음 제작 기록 | 파일·소스·결정 이유를 정리하고 다음 작업에 재사용 | 납품 manifest와 수정 이유 저장. 장기기억 후보는 별도 승인 | 유효 기억만 다음 요청에 연결, 과거 납품본 유지 | 납품 버전·권리·다음 적용 범위. 자동 공식설정 승격 금지 |

“수동 12개, 자동 8개”처럼 체크박스 개수만으로 자동화율을 계산하지 않는다. 한 업무의 일부만 자동일 수 있고, 확인 비용이 새로 생길 수 있다. 자동화의 효과는 W별 사람 능동시간, 오류·복구 시간, 최종 승인 품질을 합쳐 측정한다.

## 7.6 첫 작품과 후속 작품의 ‘네 가지 주요 결정’

### 첫 작품: 기준을 만드는 일이 추가된다

자료 수집·권리 확인 → IP 자료 등록 → 추출 후보 검토 → 캐스트·공식 설정·취향 범위 승인 → 제작 요청의 네 가지 주요 결정 → 결과 검토·수정·최종 승인 순서다. 자료가 흩어져 있거나 새로운 세계관을 창작해야 하면 도입 부담이 커질 수 있다. 이를 무료 준비 시간이나 자동 처리로 숨기지 않는다.

초기 온보딩 시간과 반복 요청 준비 시간은 06장의 대상 범위와 MET-001/002를 그대로 사용한다. 초기 기준팩의 능동 작업 P50 20분/P90 40분, 반복 요청 준비 P50 5분/P90 10분은 **미검증 목표**다. 자료 수집·권리 확인·세계관 창작·분석 대기는 따로 기록하고 전체 도입 시간도 함께 보고한다. 이 목표를 최종 MV 완료시간으로 제시하지 않는다.

### 후속 작품: 유효한 기준을 확인하며 시작한다

| 순서 | 06장과 동일한 주요 결정 명칭 | 사용자가 하는 일 | 시스템 자동화 목표 | 여전히 따로 남는 일 |
|---|---|---|---|---|
| ① | IP·곡·제작목적 | 올바른 IP와 새 곡, 길이·용도 선택 | 이전 프리셋과 자료 연결, 누락 확인 | 최초 IP 등록·새 음원 제작 |
| ② | 적용설정·시점·예외 | 적용할 시대·기준 버전·이번 곡의 예외 확인 | 유효 기억 검색, 이전 수정 이유와 충돌 제시 | 새 공식 설정·권리의 별도 승인 |
| ③ | 콘티·규모·예산승인 | 샷 구성과 적용 기준·제작 범위·비용 상한 검토 | 콘티·자산 배치·견적 제안 | 필요한 콘티 수정·승인자 간 조율 |
| ④ | 실행 | 표시된 범위의 초안 생성을 결정 | 승인된 작업 실행·진행 표시·한도 관리 | 이후 결과 선택·수정·최종 출력 승인 |

이 네 항목은 여러 입력과 세부 판단을 묶은 UX 설계다. 세 번째 항목에 콘티와 예산이 함께 있다고 해서 실제 사람이 한 번의 판단만 했다고 계측하지 않는다. `decision_group_id`와 세부 `decision_event_id`를 모두 기록하고, 같은 결정을 재검토한 횟수도 공개한다.

우리 내부 목표를 정확히 쓰면 **“기준 자산이 준비된 반복 요청에서 초안 실행 전 주요 결정 P50 4개 이하”**다. 의미 있는 UI 동작 8–12개는 설계 예산으로 남기고 실제 분포를 측정한다. 접근성 조작·입력·파일 탐색·로그인 복구를 숨겨 “4클릭”으로 바꾸지 않는다.

초안 뒤에는 후보 검토, 변경 목록 제출, 추가 견적 승인, 결과 비교, 최종 승인, 장기기억 채택이 이어질 수 있다. 단순 지원 유형에서 2회 이내 수정 완료를 목표로 하되, 06장의 MET-006처럼 중도포기와 상한 초과도 분모에 포함한다. **초안 1회+수정 1–2회는 품질 보장이나 무제한 생성권이 아니다.**

## 7.7 시간 비교는 같은 시작점과 같은 종료점으로 한다

| 시간 지표 | 시작 → 종료 | 무엇을 포함하는가 | 발표 용도 |
|---|---|---|---|
| IP 도입시간 | 자료 수집 시작 → 승인 기준 준비 | 자료 정리·권리 확인·추출·승인, 대기 | 첫 작품의 실제 부담 |
| 능동 준비시간 | 반복 요청 시작 → 실행 승인 | 자료 선택·기준 확인·기획 수정·견적 검토 | MET-002의 대상. 최종 완료시간과 분리 |
| 첫 검토본 경과시간 | 필수 입력 준비 또는 요청 시작 → 재생 가능한 첫 검토본 | 분석·대기열·생성·실패 복구·초안 조립 | 시작점을 둘 다 기록하면 자료 준비를 숨기지 않음 |
| 최종 승인 경과시간 | 같은 입력 준비 시점 → 권한 있는 최종 승인 | 초안·검토 회신·수정·복구·렌더·승인 | 공급자 납품 일정과 비교하려면 이 지표 사용 |
| 사람 노동시간 | 각 참여자의 실제 작업 구간 합 | 기획자·편집자·검토자·지원자가 수행한 일 | 자동화 효과와 노동의 이동 평가 |

한국 AI 대행 사례는 자료 전달 완료 뒤 30초/60초 패키지의 일정과 피드백 변수까지 공개한다. 일본 사례는 일괄 제작과 편집만 맡기는 플랜의 기간을 다르게 제시한다. 이들은 해당 공급자의 납기 안내이지 평균 실측이 아니다. 내부 작업시간이 공개되지 않았다면 제작비에서 시간을 역산하거나 고객이 기다린 시간을 전부 인건비로 계산하지 않는다. [WF-S02, WF-S03]

Tunee의 공식 비교표처럼 기획부터 납품까지의 주 단위 일정과 AI 생성의 분 단위 시간을 한 표에 놓으면 범위가 다를 수 있다. 우리 자료는 이를 따라 “수주에서 수분”이라고 쓰지 않는다. 생성 서버의 처리시간이 빨라도 영상 전체 확인과 의견 회신, 반복 생성, 승인에는 별도 시간이 들어간다. [WF-S07]

공정이 병렬로 진행되면 W01–W12의 경과시간 합계는 총 경과시간이 아니다. 사람 노동시간은 참여자별 합계, 경과시간은 시작과 종료의 차이로 계산한다. 비활동 탭을 열어둔 시간을 노동시간으로 계산하지 않으며, 동시에 다른 일을 할 수 있는 생성 대기와 집중 검토 시간을 구분한다.

## 7.8 가격 비교의 산출물과 현재 모델값

공통 입력은 고객이 보유한 권한 확인된 완성 음원·가사·승인 자산이다. 신규 그림, 녹음, MIX, 정확한 안무·정밀 립싱크는 비교 범위 밖이다. 외부 견적에 이 항목이 포함됐다면 같은 범위로 재견적을 받거나 포함 차이를 표시한다. 제외 항목을 임의 금액으로 빼서 맞추지 않는다.

다음 금액은 **월 4편·샷당 첫 후보 포함 2개·gen4_turbo·기존 IP의 후속 제작·세금 제외** 조건의 모델링이다. Team 월 249,000원 중 편당 62,250원을 배분하고, 외부 변동비 예산에 30%를 가산한 사용료 가설을 더한다. 이 30%는 순이익률이 아니다. 원 단위 반올림이며 계산 원본은 소수 둘째 자리까지 보존한다. 금액·산식·제외 항목은 제9장 9.3–9.5와 `output/cost_scenarios.json`을 기준으로 한다.

| 원가 시나리오 ID | 영상 구성 | 편당 사용료 가설 | 편당 고객 현금 합계 가설 |
|---|---|---|---|
| COST-060-ASSET | 60초, 제공 일러스트·가사 중심 | 1,456원 | 63,706원 |
| COST-060-HYBRID | 60초, 새 영상 50%·기존 자산 50% | 8,663원 | 70,913원 |
| COST-060-GEN | 60초, 새 영상 100% | 15,870원 | 78,120원 |
| COST-180-ASSET | 180초, 제공 일러스트·가사 중심 | 3,640원 | 65,890원 |
| COST-180-HYBRID | 180초, 새 영상 50%·기존 자산 50% | 25,262원 | 87,512원 |
| COST-180-GEN | 180초, 새 영상 100% | 46,883원 | 109,133원 |

초기 제품 실증은 30–60초의 제한된 지원 유형부터 시작한다. 위 60초 행도 실행 품질·수율을 검증한 가격이 아니며, 특히 100% 새 생성 모드는 별도 실증 통과가 필요하다. **180초 세 행은 원가 설계용이며 실행 지원과 품질이 미검증이다.** ASSET 모드는 새 영상 생성 비율이 0%이므로 gen4_turbo 영상 생성비를 사용하지 않는다. 모든 행의 고객 현금 합계는 구독 배분과 모델링한 사용료의 합이며, 실제 승인본 한 편을 확보하는 데 든 비용은 아직 측정하지 않았다. [제9장 9.3–9.5]

5초 클립과 샷당 후보 2개는 **계산 가정**이며 1개·3개 민감도를 함께 제시한다. 화면비, 인물 수, 그림체, 움직임 난이도, 음원·가사 범위, 원본 자산 상태, 포함 수정, 산출 파일, 사용권, 사람이 제공하는 서비스를 가격 행마다 붙인다. 1080p로 내보낸 파일이라도 720p 모델 원본을 보간했다면 native 1080p 생성과 품질이 같다고 말하지 않는다.

실제 고객 총현금지출을 비교할 때는 `월 구독료 배분 + 사용료 + 유료 추가 옵션 + 범위 밖 외주 + 세금/결제 비용`을 계산한다. 위 모델은 고객 노동, 첫 IP 정리 대행, 추가 외주, 세금·외환 결제 수수료 등을 제외한다. 첫 등록을 직접 하는 노동은 20분·경제가치 10,000원을 추가하는 가정이며 현금 청구가 아니다. 자료 정리 대행 199,000원부터라는 별도 판매 가설도 위 금액에 포함하지 않았다. 실제 추가 서비스가 필요하면 견적과 원가를 따로 더한다. [제9장 9.3–9.4]

월 사용 빈도의 영향은 다음과 같다. **같은 180초 HYBRID, 후보 2개, gen4_turbo** 조건이며 180초 지원이 검증됐다는 의미는 없다. 월 249,000원을 결제하는 가정이므로, 월 4편이나 8편으로 배분한 편당 수치만 구매가격처럼 표시하지 않는다. 월 합계는 반올림 전 값으로 계산했다. [제9장 9.4]

| 월 납품 편수 가정 | 편당 구독 배분 | 편당 고객 현금 가설 | 월 고객 현금 가설 |
|---|---|---|---|
| 1편 | 249,000원 | 274,262원 | 274,262원 |
| 4편 | 62,250원 | 87,512원 | 350,046원 |
| 8편 | 31,125원 | 56,387원 | 451,093원 |

공개 상품 사례에는 60초 AI MV 제작 대행 449,000원(구매 수수료 별도·수정 2회), 더 단순한 60–70초 문자·효과·소재 편집 3,000엔부터가 있다. 이는 각각의 공개 상품 조건이며, 같은 품질·서비스 범위로 우리 플랫폼과 맞춘 견적이 아니다. 엔화 사례를 비교할 때는 별도의 환율 기준을 명시한다. [제9장 9.2, DP-01/DP-03; WF-S03]

| 비교 필드 | 현재 값 또는 증거 상태 | 다음 수집과 해석 |
|---|---|---|
| 같은 범위·품질의 외부 비교 견적 | 미측정, EXP-C01에서 수집 | 공개 사례 가격과 별도로 견적일·세금·범위·수정·추가비를 확인 |
| 실제 과금·실패 후보·승인본당 고객 지출 | 미측정, EXP-C02에서 수집 | 위 계산값을 실측으로 대체. 탈락·미완료·복구 비용도 원장에 포함 |
| 고객과 제작자의 실제 노동시간 | 미측정, EXP-C03에서 수집 | 참여자별 능동시간·대기·회신·복구를 구분. 시간 절감률은 아직 없음 |
| 고객 시간의 경제적 가치 | 제9장 계산 가정: 30,000원/시간 | 60초는 25분·12,500원, 180초는 75분·37,500원. 노동시간 미측정, EXP-C03에서 수집 |
| 실제 지불의사·월 제작 빈도 | 미측정, EXP-C04에서 수집 | 월 249,000원·월 4편은 판매 실적이나 고객 평균이 아닌 가격·사용량 가설 |

수율과 최종 승인 품질이 다르면 계산상 저렴한 후보가 최종 납품 기준으로도 저렴하다고 결론 내릴 수 없다. 따라서 사업계획에는 **공급자 공개 견적, 우리 설계 원가·요금 가설, 실제 비교 결과**를 각각 다른 표제와 표식으로 둔다.

## 7.9 비교 실험과 ‘정말 그렇게 느껴지는가’의 검증

### 현실적인 비교군

1. **현재 작업 방식:** 제작자가 실제 사용하는 도구·폴더·스타일 가이드·기존 프롬프트를 허용한다. 외주라면 고객 노동과 제작자 노동의 관측 가능 범위를 나눈다.
2. **현재 AI 도구:** 관련 도구의 기본 자산 재사용·기억 기능을 허용한다. 경쟁 도구의 기록을 일부러 지우거나 제한해서 약한 비교군을 만들지 않는다.
3. **우리 플랫폼의 기억 효과 비교:** 같은 모델·자산·예산·편집·검토 도구를 유지한 채, 승인된 구조화 기억의 적용 조건을 비교한다. 기억 미적용 조건에도 동일한 원자료를 제공한다.

첫 비교는 대안에 대한 사업가치, 세 번째 비교는 기억 설계 자체의 기여를 묻는다. 각각의 결과를 섞어 “온톨로지 때문에 전부 개선됐다”고 말하지 않는다. 새 곡·작업 순서·숙련 효과가 결과를 좌우하지 않도록 대응 과제를 만들고 순서를 교차 배정한다. 06장의 EXP 설계·표본·분모를 기본으로 삼는다.

### 같은 IP의 세 프로젝트에서 관찰할 일

| 요청 | 시험 과제 | 기대하는 동작: 아직 미실행 | 실패로 기록할 상황 |
|---|---|---|---|
| 첫 작품 | 기준 머리색, 시대별 관계, 낮은 채도 선호를 등록. 과도한 클로즈업 수정 | Producer 제안과 IP 승인권자의 장기 취향 채택을 분리 | 결과물의 우연한 소품이나 가사 은유가 공식 사실이 됨 |
| 두 번째 작품 | 새 곡의 후렴만 밝게, 지난 클로즈업 교정은 유지 | 이전 교정이 브리프·장면에 연결되고 후렴 예외는 이번 작품에만 적용 | 같은 오류 재발, 새 예외가 IP 전체 취향을 덮음, 매번 모든 자료 재입력 |
| 세 번째 작품 | 새 시대로 이동, 일부 관계 변경 | 유효 시점에 따라 기준을 달리 쓰고 이전 완성본은 보존 | 새 기준이 과거 승인본을 바꾸거나 시대를 혼동 |

세 작품은 평가의 시작 단위이지 학습 완료 횟수가 아니다. 기준 카드에 “기억했습니다”라고 표시되는 것만으로 성공 판정하지 않는다. 실제 장면의 오류, 사용자의 수정량, 검토 시간, 블라인드로 본 ‘우리 IP답다’ 평가, 새로움과 곡 적합성까지 함께 확인한다.

### 발표 주장으로 승격할 최소 계측

| 주장 후보 | 필요한 기록 | 실패·누락 처리 | 연결 지표 |
|---|---|---|---|
| 초안 실행 전 네 가지 주요 결정 | 시작·종료 이벤트, 결정 묶음과 세부 이벤트, 반복 결정, 보조 입력 | 중도 이탈과 재시작을 제외하지 않음 | MET-003/004 |
| 반복 준비가 빨라짐 | 같은 구간의 사람 능동시간, 모든 참여자, 온보딩 배분 전후 | 대기·복구·지원 시간을 별도로 공개 | MET-001/002/009/028 |
| 두 번 이내 수정으로 완료 | 처음 배정한 적격 요청 수, 검토본·변경 목록·최종 승인 | 포기·상한 초과·대체 제작도 실패 또는 별도 결과 | MET-006 |
| 기억이 실제 장면을 개선 | 적용 근거 manifest, 장면별 위반, 승인 기록, 블라인드 평가 | 근거 검색 성공이 영상 성공을 대체하지 않음 | MET-007/008/011/016–021 |
| 총비용 절감 | 구독 배분·사용료·과금 실패·사람시간·외주·승인품질 | 채택된 영상만 세고 탈락 후보비를 제외하지 않음 | MET-022/023/027 |

시제품 사용성 관찰은 화면 구조와 문구의 문제를 찾는 데 쓸 수 있지만, 생성 품질이나 실제 지불 의사를 입증하지 못한다. 내부 기술 데모, 사용성 실험, 실제 유료 반복 사용을 각각 다른 증거로 보고한다. 결과를 공개할 때는 표본 수, 요청 범위, 모델 버전, 측정일, 중앙값·상위 지연, 중단 비율과 품질 기준을 붙인다.

## 7.10 사업계획·PPT용 주장 카드 10장

다음은 슬라이드에 옮길 내용 설계다. 완성된 PPT나 실행 제품의 화면을 만들었다는 뜻이 아니다. 카드마다 사용 가능한 표현과 증거 한계를 함께 제공한다. 금액은 제9장의 공개 상품 사례와 원가모델을 사용한다. 아직 실행하지 않은 성과는 ‘미측정’과 수집 실험으로 표시하고, 실제 결과를 얻은 뒤 문장을 갱신한다. 가정과 미검증 상태는 발표자 메모에만 숨기지 않고 해당 슬라이드에 함께 넣는다.

### 카드 01 — 우리가 해결하려는 일

- **헤드라인:** “다음 곡을 만들 때, 지난 결정부터 이어지는 제작 공간.”
- **본문:** 아이돌 기준·시대·취향·이전 수정 이유를 제작 요청과 연결한다. 이번 작품의 예외와 IP 전체 기준을 나눈다. 결과 검토와 승인은 사람이 맡는다.
- **시각 구성:** 첫 곡·두 번째 곡·세 번째 곡 아래에 같은 기준 버전과 승인된 수정의 연결을 표시. 예시 IP는 가상 테스트 데이터로 표기.
- **지금 사용 가능:** “이런 제작 흐름을 설계하고 있다.”
- **가설로만 가능:** “반복 설명과 같은 오류의 재발을 줄이는 것이 목표다.”
- **실측 후 가능:** 조건·표본과 함께 반복 설명 시간·특정 오류 재발의 실제 변화를 보고한다. 현재 미측정, EXP-C03과 제6장 기억 평가에서 수집한다.
- **주석:** 제품 구현·효과 미검증. 기억 개념 자체는 경쟁 도구에도 존재. [WF-S11]

### 카드 02 — 기존 제작도 여러 방식이 있다

- **헤드라인:** “일러스트 외주, 일괄 제작, AI 대행, 직접 제작을 분리해 비교한다.”
- **본문:** Saraemi의 사례는 공정 제목 5개, Tsunagu의 일괄 의뢰는 공개 순서 8개, 한국 AI 대행은 업무 명칭 6개다. 이 숫자는 시장 평균이 아니다.
- **시각 구성:** 공급자별 짧은 순서표와 산출물 범위. 같은 높이의 막대로 속도를 암시하지 않는다.
- **지금 사용 가능:** “선택한 공개 사례는 이렇게 진행한다.”
- **가설로만 가능:** “이 중 기준 확인·자산 연결·선택 수정 업무를 통합하면 협업 부담이 줄 수 있다.”
- **실측 후 가능:** 같은 길이·자산·품질 조건에서 방식별 능동시간·납품시간 비교. 현재 미측정, EXP-C01의 범위 맞춘 견적과 EXP-C03의 작업 관측에서 수집한다.
- **주석:** 공정 수≠고객 조작 수. [WF-S01, WF-S02, WF-S03]

### 카드 03 — ‘12 → 4’ 대신 같은 단위를 쓴다

- **헤드라인:** “12개 업무를 연결하고, 초안 실행 전 결정을 네 가지 묶음으로 설계.”
- **본문:** 12는 W01–W12 분석용 업무 목록, 4는 반복 요청의 UX 목표다. 결과 검토·수정·최종 출력은 이어서 수행한다.
- **시각 구성:** 위쪽 12개 업무와 아래쪽 사람·자동화의 담당 표. ‘−67%’ 배지·감소 화살표를 쓰지 않는다.
- **지금 사용 가능:** 서로 다른 단위를 구분한 설계 설명.
- **가설로만 가능:** “초안 실행 전 주요 결정 P50 4개 이하, 의미 있는 UI 동작 8–12개를 목표로 한다.”
- **실측 후 가능:** 동일 정의로 측정한 결정·UI 동작 분포. 현재 미측정, EXP-C03에서 수집한다.
- **주석:** 초기 설정과 결과 승인 별도. MET-003/004. 현재 측정값 없음.

### 카드 04 — 첫 작품과 후속 작품의 차이

- **헤드라인:** “처음에는 기준을 만들고, 다음에는 바뀐 점을 확인한다.”
- **본문:** 첫 작품에는 자료·권리·공식 설정·취향을 준비하는 비용이 있다. 후속 작품은 ①IP·곡·제작목적 ②적용설정·시점·예외 ③콘티·규모·예산승인 ④실행으로 구성한다.
- **시각 구성:** 첫 작품에는 별도 온보딩 구간, 후속 작품에는 기준 재사용 구간. 둘 다 결과 검토·수정·승인 구간을 표시.
- **지금 사용 가능:** 설계된 역할과 입력 범위.
- **가설로만 가능:** 준비된 기준팩에서 도입과 반복 요청 준비 시간 목표를 분리해 설명.
- **실측 후 가능:** 같은 IP의 3개 요청 합계에서 온보딩을 포함한 사람 시간의 변화를 보고한다. 현재 미측정, EXP-C03에서 수집한다. 감소를 관측하지 못하면 절감 문구를 사용하지 않는다.
- **주석:** 세 작품으로 학습 완료를 보장하지 않음. MET-001/002/009.

### 카드 05 — 사람이 남겨야 할 결정

- **헤드라인:** “자동화는 제안과 실행을 맡고, 승인 기준은 사람이 정한다.”
- **본문:** IP 승인권자는 공식 설정·장기 취향·권리를, Producer는 제작 방향과 위임된 최종 납품을, 지출 권한자는 한도를 승인한다. 같은 사람이 여러 역할을 맡아도 승인 종류와 대상 버전은 구분한다.
- **시각 구성:** 후보→공식 기준, 초안→납품본, 견적→유료 실행의 세 승인 경계만 보여준다.
- **지금 사용 가능:** 요구서의 권한·승인 설계.
- **가설로만 가능:** “지나치게 많은 확인 없이 책임 있는 통제를 제공한다.”
- **실측 후 가능:** 권한 위반·오승인·승인 피로와 검토 시간의 관측 결과. 현재 미측정이며 제6장 권한·승인 평가와 EXP-C03에서 수집한다.
- **주석:** 생성물 선택이 공식 설정 승인이 되는 흐름은 금지. 제품 실행 검증 전.

### 카드 06 — 시간은 ‘생성’과 ‘최종 납품’을 나눈다

- **헤드라인:** “빠른 생성보다, 승인까지 걸리는 전체 시간을 측정한다.”
- **본문:** 공개 납기는 공급자의 범위·자료 준비·피드백 조건과 함께 제시한다. 우리의 준비·서버 처리·검토·수정·출력 시간을 분리한다.
- **시각 구성:** 동일 시작점에서 첫 검토본과 최종 승인 두 종료점을 표시한 누적 시간표. 미측정 칸은 ‘미측정’으로 둔다.
- **지금 사용 가능:** 공개 일정과 생성시간의 분모 차이 설명.
- **가설로만 가능:** “반복 준비시간 감소를 목표로 한다.”
- **실측 후 가능:** 동일 조건의 최종 승인시간 P50/P90와 미완료 비율을 보고한다. 현재 미측정, EXP-C02/EXP-C03에서 수집한다. 첫 초안 처리시간과 최종 승인시간을 별도 표시한다.
- **주석:** ‘몇 주→몇 분’ 단정 금지. [WF-S02, WF-S03, WF-S07]

### 카드 07 — 가격은 최종 승인본 한 편의 총액으로

- **헤드라인:** “월구독과 외주 한 편을 직접 비교하지 않는다.”
- **본문:** 제9장 모델에서 60초 ASSET 63,706원, HYBRID 70,913원, GEN 78,120원은 월 4편 기준의 편당 현금 가설이다. 월 구독 249,000원의 편당 배분 62,250원과 사용료를 합산했다. 180초 HYBRID는 같은 조건에서 87,512원이지만 실행 지원·품질이 미검증이다.
- **시각 구성:** 60초 세 모드의 구독 배분·사용료 누적 막대에 ‘모델링’ 표시. 180초는 별도 계산 사례로 제시한다. 월 1·4·8편에서 180초 HYBRID 편당 274,262원·87,512원·56,387원임을 같은 화면의 빈도 표에 표시한다. 외주 사례와의 감소율·품질 등가 배지는 넣지 않는다.
- **지금 사용 가능:** “공개 상품에는 60초 AI 제작 대행 449,000원(구매 수수료 별도·수정 2회), 더 단순한 60–70초 편집 3,000엔부터가 있다. 각 상품의 서비스 범위가 다르다.” [제9장 9.2, DP-01/DP-03]
- **가설로만 가능:** 위 금액 옆에 ‘월 4편·gen4_turbo·샷당 후보 2개·후속 제작·세금 제외·미검증 요금 모델’을 붙인다. ASSET에는 새 영상 생성이 없다. 후보 2개는 완성본 수정 2회가 아니다. [제9장 9.3–9.5]
- **실측 후 가능:** 같은 품질·지원 범위의 승인본당 실제 총지출 비교. 범위를 맞춘 외주 견적은 미측정, EXP-C01에서 수집한다. 실제 과금·실패 포함 비용은 미측정, EXP-C02에서 수집한다. 고객 노동은 미측정, EXP-C03에서 수집한다.
- **주석:** 고객 노동·신규 그림·녹음·MIX·정밀 안무/립싱크·세금 등은 금액에서 제외. 제공 원본 사용. 월 구독료·사용량은 확정 판매 실적이 아니며 EXP-C04에서 검증한다. 보간 1080p와 native 생성 품질을 구분한다.

### 카드 08 — 경쟁 우위는 반복 제작에서 확인한다

- **헤드라인:** “한 편 생성은 이미 경쟁이 치열하다. 우리는 다음 편의 교정 비용을 검증한다.”
- **본문:** 기존 AI 도구의 기획·편집·기억 기능을 인정한다. 우리 비교는 아이돌 기준, 시점·예외, 실제 장면 반영, 부분 수정, 승인·비용 기록에 집중한다.
- **시각 구성:** 기능 체크표 대신 검증 질문과 증거 칸. ‘경쟁사 없음’에는 체크하지 않는다.
- **지금 사용 가능:** 각 도구의 공식 기능 설명과 우리 검증 범위.
- **가설로만 가능:** “음악·아이돌 운영에 맞춘 기억 통제가 반복 제작에서 더 유용할 수 있다.”
- **실측 후 가능:** 경쟁 도구의 재사용 기능을 허용한 대응 과제의 품질·시간·비용 결과. 현재 미측정, 제6장 품질 평가와 EXP-C02/EXP-C03에서 수집한다.
- **주석:** [WF-S07–WF-S12]. 기능 존재와 실제 성능은 구분.

### 카드 09 — 세 작품으로 보여줄 데모와 판정

- **헤드라인:** “지난 교정은 남고, 이번 곡의 예외는 새어 나가지 않아야 한다.”
- **본문:** 1편에서 클로즈업 감소를 승인, 2편에서 재사용, 3편에서 시대가 바뀌어도 과거 납품본은 유지한다. 근거 카드뿐 아니라 결과 장면과 수정 원장을 확인한다.
- **시각 구성:** 가상 IP의 세 요청, 기대 결과, 실제 결과/미실행 상태를 나란히 표시.
- **지금 사용 가능:** 시험 시나리오와 성공·실패 정의.
- **가설로만 가능:** 2회 이내 수정·IP다움·시간 감소의 06장 목표.
- **실측 후 가능:** 배정 요청 전체를 분모로 한 완료율, 블라인드 평가, 반복 오류·비용 결과. 현재 미측정, 제6장 평가와 EXP-C02/EXP-C03에서 수집한다.
- **주석:** 데모 성공 한 건을 고객 성공률로 확대하지 않음. 자동 근거 일치가 시각 품질 통과를 대신하지 않음.

### 카드 10 — 현재 상태와 다음 증거

- **헤드라인:** “현재는 설계와 공개자료 조사. 다음 단계는 제한 범위의 유료 반복 검증.”
- **본문:** 초기 검증은 30–60초의 단순 지원 유형이다. 180초·다인 군무·정밀 립싱크는 검증된 범위와 분리한다. 기술 실행, 사용성, 유료 반복 사용의 결과를 각각 확보한다.
- **시각 구성:** 공개자료 확인 / 제품 실행 미검증 / 고객 반복 성과 미측정의 상태표. 완료처럼 채운 그래프 사용 금지.
- **지금 사용 가능:** 조사 완료 항목·요구서·실험 설계의 존재.
- **가설로만 가능:** 어떤 조건에서 사업화에 진전할지의 사전 기준.
- **실측 후 가능:** 표본·모델·기간·유료 여부·지원 개입을 포함한 실제 성과 문장. 현재 미측정, EXP-C01~C04와 제6장 검증을 마친 뒤 근거에 맞춰 작성한다.
- **주석:** Aethon의 성과·고객·실험을 신규 플랫폼의 결과로 승계하지 않음.
