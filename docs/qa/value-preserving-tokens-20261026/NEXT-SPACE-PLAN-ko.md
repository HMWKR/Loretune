# 다음 화면 공간·위계 묶음 — 계획, 미구현

기준은 [완료된 토큰 배치](REPORT-ko.md)의 고정 소스와 실제 서버 캡처다. **이 문서 작성 시 레이아웃 수정은 0이다.** 한 명의 코드 writer가 아래 한 가지 공간 변경만 구현하는 안을 먼저 설명한다. 새 팔레트·폰트·패키지·공급자·전면 CSS 정리는 포함하지 않는다.

## 사용자 과업과 관측

과업은 같은 장면의 영상과 음악·자막을 보면서 편집을 판단하는 것이다. 실제 사용자 관찰 연구가 아니라 현재 합성 작업 화면의 전문가 점검이다. 참고 방향은 기존 [reference lock](../design-system-redesign-20261026/REFERENCE-LOCK.md)과 [방법론 적합표](../design-system-redesign-20261026/METHODOLOGY-FIT-MATRIX-ko.md)를 유지한다. 관련 도구와 결과를 인접 배치하고 덜 자주 읽는 상세 설명을 접는 원칙을 적용하되, 특정 픽셀 값이 외부 표준의 정답이라는 주장은 하지 않는다.

근거는 각 `1920/1280-*.json`의 `metrics.boxes`와 저장 이미지다. 모든 상태의 미디어·타임라인·자막을 없애지 않고, 먼저 **제목과 접힌 설명의 중복된 수직 자리**를 회수하는 것이 가장 좁은 후보다. 현재 프레임의 수동 컨테이너 테두리를 모두 약화해야 한다는 새 결함 근거는 없으므로 border 묶음은 보류한다.

## 선택안과 대안

**선택안:** bounded desktop에서 제목·현재 편집 Take 표시·‘장면 설명’ summary를 한 문맥 헤더의 같은 행에 배치한다. 설명을 열면 원문 전체를 같은 문맥 아래에 표시한다. 목표는 접힌 상태의 현재88px를 약44px의 행으로 구성하는 것. 정확한 절감량은 구현 후 측정해야 한다.

예상 소스 범위는 `index.html`의 `initializeCreatorUI()` 설명 details 생성/배치(:228 부근), 기존 shot header 구성(:646 부근), `studio.css`의 bounded header/description 규칙(:866–868 부근)이다. 현재 ID·native details/summary·본문을 재사용하며, 작은 배치 wrapper가 필요하면 그 하나로 제한한다. 새 저장 상태나 전역 controller를 만들지 않는다. 선택·승인·재생·비교 handler는 변경하지 않는다.

|대안|판정 이유|
|---|---|
|현재 배치 유지|위험은 가장 적지만 이미 확인된 영상 공간 제약을 줄이지 못함|
|**제목+설명 접힌 행 결합**|내용·행동을 지우지 않고 반복된 높이를 회수. 현재 작은 범위로 선택|
|timeline dock 최소 높이 추가 축소|이미 dock/precision 내부 스크롤이 있어 편집 조작 접근을 악화할 수 있음. 첫안에서 제외|
|자막·상태·seek 제거 또는 글자 축소|필수 정보/가독성 손실이므로 제외|
|상세 편집 전체를 새 inspector로 이전|범위와 상호작용 변화가 커서 이번 작은 묶음에서는 제외|
|passive border 전역 약화|입력·focus·선택·승인 구분을 해칠 수 있고 현재 증거가 부족. 개별 근거 전까지 보류|

제약/트레이드오프: 긴 한글 장면명이나 앱200%에서 같은 행을 강제하지 않고 줄바꿈한다. 따라서 모든 콘텐츠에서44px를 보장하지 않는다. 설명 펼침 시에는 높이를 쓰는 것을 허용하고 기존 내부 스크롤로 접근한다. 설명을 overlay로 띄워 영상이나 조작을 가리지 않는다. 기존 중성 팔레트, 글자·line-height·숫자폭, 선택/재생 장면 구분,44px summary 접근 목표를 유지한다.

## 비교와 통과 조건 — 제안 제품 기준

1. **현재 값 그대로 before 사용:** 1920×1080 주 기준,1280×900 보조 기준, 같은 합성 프로젝트·장면·Take·승인 상태·DPR1·앱100%. 선택/sequence × 정밀 접힘/펼침을 각각 비교한다. 선택 원본1.000초, sequence 편집0.500초(원본0.750초), 정지/ready 상태를 고정한다. native controls와 playhead도 비교 조건에 기록한다.
2. **보이는 개선:** 접힌 설명의 sequence 기본/정밀 상태에서 실제 contain 영상 높이를1920은 최소32px,1280은 최소24px 늘리는 것을 최초 목표로 제안한다. 다른 기본 상태는 현재 영상 크기보다 줄지 않아야 한다. 이는 실험할 제품 목표이며 이미 달성한 결과나 WCAG 수치가 아니다. 제목·본문 확대/줄바꿈 조건에는 이 증가량을 강제하지 않는다.
3. **접근 보존:** 표준 배율 document는1920×1080/1280×900 유지. `overflow:hidden` 추가로 조작을 숨기지 않는다. 타임라인·파형·시간눈금·playhead의 좌표, 캡션, 재생/비교·선택·검토·저장 조작, 비용/모델/권리/테스트표시는 유지한다. 기존 내부 스크롤로 정밀 입력·저장 버튼과 focus가 보인다.
4. **설명·제목:** 키보드로 summary 열기/닫기, focus 표시, 전체 긴 제목과 설명 접근, 열린 상태의 읽기 순서를 확인한다. 상호작용 대상 중첩을 만들지 않는다.1280/app200%, 긴 비분리 제목, 두 줄 자막에서 잘림·겹침·강제 nowrap 없음. 앱 배율과 실제 브라우저 zoom은 별도로 기록한다.
5. **행동 회귀:** F07·두 폼 입력 revision·unknown 중복 방지·FQ/DM 기존 guards를 유지. 공통 시간/비교 진입, Take 선택과 승인 구분, 정밀 초안 보존·취소 확인. 합성 fixture/통제 응답을 사용하고 canonical DB 쓰기·외부 생성은 하지 않는다.
6. **완료 증거:** 작은 source diff, targeted+전체 비HTTP 회귀, static 검사, exact served/source hash, 같은 상태 전후 이미지와 computed 치수, 종료/보존 기록. 전체 키보드/실제 zoom 등을 못 했으면 미검증으로 남긴다. 새 품질점수나 사용자 성공률을 만들지 않는다.

## 실행 순서와 복구

계획 설명 → 현재 두 파일 snapshot/hash 확인 → 단일 header 배치 변경 → 정적/관련 회귀 → 격리된 기존 합성 프로젝트의 실제 localhost 화면 측정 → 같은 조건 픽셀 확인 → 전체 회귀·해시 고정·정리 → 독립 읽기 검토. 실패하면 이 묶음의 작은 diff만 복구하며 기존 사용자 변경·DB·명세를 reset하지 않는다. 효과가 기준에 못 미치면 보고하고 다른 패널을 자동으로 이어서 줄이지 않는다.

현재 기술 blocker는 없다. 다음 실행에는 기존 승인된 동일 synthetic 자료/localhost/Ego 검증 범위를 유지하고 필요한 정식 실행 심사를 따른다. 새로운 recipient나 데이터가 필요하면 별도로 범위를 알린다. Library 차단은 별개이며 이 계획에 업로드는 없다. **다음 단계는 위 계획 설명 후 구현이며 지금은 소스를 고정한다.**
