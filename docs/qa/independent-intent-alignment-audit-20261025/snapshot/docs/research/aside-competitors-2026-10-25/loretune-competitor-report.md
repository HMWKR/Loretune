# 경쟁사 통합 비교 — 관찰과 실제 테스트 결과

조사 기준일: 2026-10-25. 문서 정리 완료와 제품 전체 검증 완료는 다르다.

## 핵심 결과

12개 서비스의 공개 페이지·앱 진입·일부 내부 기능을 관찰했다. 전체 기능을 빠짐없이 실행하지 못했다. 승인된 가입은 MusicMV와 1MV 2건, 비식별 합성 파일 업로드는 MusicMV 2건·Tunee 1건이다. VisionStory에서 생성 클릭 1회를 수행했지만 구독 요구로 차단되어 확인된 렌더 접수·완료는 0건이다. 확인된 차감은 0이며, 모든 서비스의 최종 영상 품질·실제 렌더 시간·다운로드 품질은 미검증이다.

REA 6.7.0 연결은 실제 성공했다. Neural Frames 공개 JS 분석은 소유권 확인 실패로 전체 호출이 실패했지만 부분 Evidence 요약·모듈 참조 조회는 성공했다. 나머지 11개 서비스에는 성공한 REA 제품 분석 Evidence가 없다. 서버 내부 구조를 확인한 것으로 해석하면 안 된다.

## 디자인과 UX에서 확인한 차이

- 입력과 가격을 같은 작업 화면에 모으는 MusicMV·BeatViz 구조는 비교가 쉽다. 다만 견적이 보인다는 사실만으로 실제 무료 사용이 보장되지는 않았다.
- VisionStory는 무료 잔여보다 적은 견적이 나와도 생성 클릭 뒤 구독 게이트가 나타났다. 모델 사용 자격과 크레딧 잔여를 별도로 안내할 필요가 있다.
- 1MV는 공개가 기본 ON이고 비공개 전환이 유료였다. 생성 전 공개 범위·재사용 동의를 각각 분리하는 것이 중요하다.
- Tunee의 업로드 후 음악 분석 내용은 사용자가 수정할 수 있었다. 자체 120 BPM 합성 입력을 다른 장르·115 BPM으로 표시한 관찰이 있었으므로 분석 결과를 확정 사실로 취급하지 않아야 한다.
- Revid의 빈 초안 자동 저장은 렌더 결과와 다르다. 초안·접수·실패·완료의 상태를 구분해야 한다.

정확한 폰트·HEX·간격 토큰·반응형 브레이크포인트·대비 점수는 측정하지 않았다. 개별 보고서의 시각 묘사는 화면 관찰이며 디자인 토큰 제안은 경쟁사 실측값이 아니다.

## 확정할 수 없는 내용

서버 작업 큐·모델 공급자 호출·DB 스키마·과금 원자성·인프라 구성은 검증하지 않았다. 공개 화면의 모델명·성능 설명은 운영 구현 증거가 아니다. 모바일·키보드·스크린리더 전체 검증도 수행하지 않았다.

# Loretune 적용 계획 — 검토용 제안

## 상태와 근거

이 문서는 경쟁사 실제 UI 관찰과 실패 사례에 기반한 제안이다. Aside의 프로젝트 읽기는 OS 접근 거절로 실패했고, 이 문서 작성 과정에서도 코드 구현을 대조하지 않았다. 현재 기능이 없다고 단정하지 않으며 구현·DB·서버 변경은 수행하지 않았다. 순서는 조사 한계 확인 → 계획 검토 → 기존 코드와 대조 → 구현이다.

## 1. 생성 전 조건을 한곳에서 확인

입력 검증, 모델 사용 자격, 무료/유료 잔여, 예상 차감, 결과 공개 범위, 워터마크·다운로드 가능 여부를 생성 버튼 주변에 묶는다. 견적과 자격은 분리해 표시한다. 모델·길이·해상도 변경 시 견적을 갱신하고 산정 중에는 접수를 막는다. 비공개 기본값과 원본 재사용 동의는 독립 설정으로 둔다.

수락 기준: 무료 잔여가 있어도 모델 사용이 불가능하면 버튼을 누르기 전에 이유가 보인다. 공개 설정이 유료이거나 변경 불가하면 입력 업로드 전에 알 수 있다.

## 2. 입력과 분석 결과를 사용자가 검토

음원 업로드 진행·실패·형식·길이·선택 구간을 명확히 표시한다. BPM·장르·보컬 여부는 분석 추정과 사용자 수정값을 구분한다. 기존 음원·합성 테스트·내장 예제의 출처를 구분하고 사용자 소유권 확인을 별도로 둔다.

수락 기준: 분석값 수정 후 저장·재진입 때 유지되고, 원본과 수정값을 구분할 수 있다. 오류가 나도 성공한 업로드를 다시 요구하지 않는다.

## 3. 스토리보드와 렌더 상태를 분리

Draft → Analyzing → Storyboard ready → Render queued → Rendering → Complete/Failed 상태를 설계 검토한다. 스토리보드 준비 메일은 최종 영상 완료 메일과 제목·링크·상태를 구분한다. 접수 결과가 불확실하면 작업 조회를 우선해 중복 생성과 과금을 막는다.

수락 기준: 새로고침·재접속 뒤 같은 작업으로 복귀하며, 각 알림이 특정 프로젝트·샷·작업과 연결된다. 이 상태 모델은 제안이며 경쟁사 서버 구현의 복원이 아니다.

## 4. 샷 단위 수정과 비용 통제

음악 구간·샷·캐릭터·첫 프레임·생성 결과의 관계를 한 화면에서 보이게 한다. 부분 수정의 영향 범위와 재생성 비용을 제출 전에 표시한다. 완료 결과와 실패·취소·예상 비용을 구분하고 재시도 횟수를 기록한다.

수락 기준: 한 샷 변경이 전체 재생성인지 부분 재생성인지 사용자에게 명확하다. 렌더가 완료되지 않은 초안을 완성 결과처럼 표시하지 않는다.

## 5. 디자인·접근성

작업 영역은 입력/스토리보드/프리뷰의 우선순위를 유지하고 보조 도구는 점진적으로 노출한다. 기존 Loretune 디자인 시스템을 먼저 확인한 뒤 색·간격·타이포그래피 토큰을 정한다. 경쟁사 스크린샷에서 추정한 수치를 복제하지 않는다. 키보드 이동, 초점 표시, 이름 없는 생성 아이콘의 접근성 이름, 상태 알림, 작은 화면에서의 도구 접근을 검증한다.

## 단계별 검증 계획

1. 기존 코드·명세와 제안의 중복/차이를 확인하고 변경 범위를 확정한다.
2. 결제 없이 가능한 합성 입력 시나리오로 입력→초안→접수→완료·실패 상태를 검사한다.
3. 같은 접수 재시도·새로고침·오류 뒤 복귀 시 중복 작업과 과금 방지 동작을 검증한다.
4. 무료/유료·공개/비공개·다운로드 조건별 표시를 확인한다.
5. 데스크톱·모바일·키보드·스크린리더를 실제 검증하고 결과를 별도 기록한다.

## 아직 결정하면 안 되는 항목

경쟁사 생성 품질·지연·실패 환불이 검증되지 않았으므로 모델/벤더 선정과 성능 우위를 단정하지 않는다. REA가 복구되기 전 서버 구조를 추정해 구현하지 않는다. 현재 문서는 실행 승인이나 구현 완료가 아니다.

# REA 6.7.0 지원 요청용 최소 오류 보고서

## 증상

Aside에서 mcp__REA__binary_session은 성공한다. mcp__REA__analyze_javascript_application은 공개 JavaScript의 부분 결과를 남기지만 cleanup_incomplete로 실패한다. 같은 입력의 새 허용 시도에서도 재발했다. 추가 실행·프로세스 조작은 중단했다.

## 환경과 입력

- macOS arm64; REA/rea-agents 6.7.0, Aside MCP client aside-browser 1.26.1024.24.
- 분석 형식 directory. Neural Frames 공개 페이지에서 받은 index-101cccd2a3df7a34.js, Login-bf41993a33b74436.js, _buildManifest.js.
- 선택 입력 총 52,769바이트. 공개 텍스트만 대상으로 하며 비밀·쿠키·계정 데이터는 입력하지 않았다.
- detail: summary, analysis_timeout_ms:30000, max_heap_mb:512.

## 정확한 오류

code: cleanup_incomplete; category: execution_failure; retryable:false.
provider_id: javascript-static-analysis; operation: analyze_javascript_application.
진단: process ownership token could not be read for 1 live process(es): reader_failure=1; live candidates 22118=reader_failure.
worker_pid:22118. PID는 오류 발생 당시 식별자이며 현재 소유권/생존 여부를 보장하지 않는다.
공식 응답: Provider cleanup could not be fully confirmed. Review the reported local resources before opening another target.

## 수행한 확인

현재 binary_session의 open:false/cleanup_pending:false는 이전 워커 정리 완료를 보장하지 않는다. 새 분석 실패 후 보존 Evidence의 요약·모듈 참조 조회와 정식 번들 export는 성공했다. 과거 ID만 조회한 missing 오류와 새 호출의 cleanup 오류를 구분했다. ps 접근 거절을 우회하거나 종료 명령을 실행하지 않았다.

## 재현 정보와 사용자가 할 수 있는 다음 행동

지원팀에 버전·도구명·공개 입력 파일명·위 오류를 전달하고, macOS reader_failure의 지원되는 진단 방법과 소유권 확인/정리 절차를 요청한다. 이 문서는 지금 같은 분석을 반복하라는 실행 지시가 아니다.

공식 설치 문서는 일부 바이너리 제공자의 실패 원인 처리 후 같은 연결에서 close_binary를 재시도하는 흐름을 설명한다. 이를 JavaScript 워커에 적용해도 안전한지 확인되지 않았고 close_binary는 세션 자료 폐기 효과가 있으므로 실행하지 않았다. 설치·권한 변경·PID만을 근거로 한 종료·임시 폴더 삭제를 해결책으로 권하지 않는다. 필요한 조치는 지원팀이 해당 워커의 소유권과 제공자별 정리 동작을 확인한 뒤 정해야 한다.

공식 근거: https://github.com/morluto/rea/blob/main/docs/installation.md 및 실제 MCP 오류 응답. 원시 인증 응답·내부 대화·개인 경로는 이 문서에 포함하지 않았다.

## 1. 최종 결론·관찰/미확인 범위

- Freebeat는 음악 입력과 프롬프트/파일 입력을 제시하는 음악 영상 제작 화면으로 관찰됐다.
- 로그인 성공 뒤 별도 가입·추가 권한·추가 인증 UI는 관찰하지 않았다.

- 무료 잔여 수치는 화면에서 확인되지 않았다.
- 실제 견적과 결과 공개 기본값도 확인되지 않았다.
- 따라서 무료 품질, 출력물, 워터마크 제거 권한을 확정하지 않는다.

## 2. 메뉴·정보구조

- 음악 업로드 시작점이 관찰됐다.
- 프롬프트 또는 파일 입력 경로가 관찰됐다.
- MV 제작 항목이 보였다.
- 댄스 제작 항목이 보였다.
- 리릭 제작 항목이 보였다.
- 실시간 MV 항목이 보였다.
- Photo Karaoke와 온비트 효과 항목도 보였다.
- 이는 기능 표면의 관찰이며 각 기능의 내부 단계를 실행한 기록은 아니다.

## 3. 제작동선·입력→작업→결과 연결

- 음악 업로드 또는 프롬프트/파일이 시작 입력으로 제시됐다.
- 16:9와 720p 선택 항목이 제작 폼에 보였다.
- 자막 제어와 워터마크 제거 토글이 보였다.
- Fast와 Freebeat 2.0 표기도 선택 문맥에서 관찰됐다.
- 실제 입력 파일을 넣지 않았으므로 활성화 조건은 미확인이다.
- 생성 버튼 클릭, 작업 접수, 렌더 대기는 미실행이다.
- 결과·다운로드·게시 연결은 미확인이다.

## 4. 상태·오류·수정·재사용

## 5. 디자인 관찰과 Loretune 제안의 분리

### 관찰

- 한 제작 화면에 모델·속도·비율·자막·워터마크 관련 선택이 함께 있다.

- 측정한 px, hex, 폰트, 접근성 점수는 없다.

### Loretune 제안

- 모델 선택과 무료 권한 여부를 같은 위치에서 명확히 구분한다.
- 워터마크 제거처럼 플랜 의존 가능성이 있는 토글에는 즉시 조건을 붙인다.
- 입력 단계에서 결과 형식과 개인정보/공개 범위를 명시한다.
- 이는 관찰 기반 제품 제안이며 구현 감사나 코드 비교가 아니다.

## 6. 레이아웃·반응형·접근성

## 8. 스크린샷 출처·시각·한계

## 9. 도구명/EvidenceID/범위 및 채택/피할점

- 분석 유형: 기존 일반 브라우저 관찰과 보존 폼 캡처
- REA 제품분석 Evidence: 이 사이트에는 없음
- 생성 결과: 0건, 품질: 미검증/미완료

## 1. 최종 결론·관찰/미확인 범위

- VisionStory는 AI 비디오와 Seedance 중심의 생성 화면으로 관찰됐다.
- 생성 클릭은 실제로 1회 수행했다.
- AI 도구 사용에 구독이 필요하다는 안내로 차단됐고 접수는 0건이다.
- 잔여는 Free 10에서 Free 10으로 유지됐다.
- 선택된 구성은 Seedance 2.0 Mini, 4초, 720p, 16:9, 8크레딧이었다.
- 결과 영상·품질·실차감·환불은 검증하지 않았다.

## 2. 메뉴·정보구조

- 좌측에 AI 비디오 항목이 관찰됐다.
- AI Agent 항목이 관찰됐다.
- 바이럴 뮤직 항목이 관찰됐다.
- 얼굴 교체 항목이 관찰됐다.
- Seedance 2.5 항목이 관찰됐다.
- 비디오 팟캐스트와 AI 프레젠테이션 항목이 보였다.
- AI 도구 항목도 보였다.
- 내부 메뉴의 기능 범위는 클릭으로 전부 검증하지 않았다.

## 3. 제작동선·입력→작업→결과 연결

- 화면은 비디오 생성, 이미지를 비디오로, 시작 및 종료 프레임 탭을 제시했다.
- 프롬프트 입력란에 비식별 기하 도형 애니메이션 설명이 있었다.
- 파일 추가 제어가 보였다.
- 모델은 Seedance 2.0 Mini로 표시됐다.
- 해상도·길이·비율은 720p·4초·16:9로 표시됐다.
- 생성 클릭 1회 뒤 구독 게이트가 나타났다.
- 작업 접수·렌더·결과·다운로드는 모두 미실행이다.

## 4. 상태·오류·수정·재사용

- 구독 요구 안내는 생성 완료가 아닌 차단 상태로 기록한다.
- 요청 ID, 큐 위치, 진행률은 확인하지 못했다.
- 실패 메시지인지 결제 전 게이트인지 외의 오류 상태는 미확인이다.
- 재시도는 하지 않았다.
- 결과 편집, 프레임 변경 후 재생성, 버전 관리도 미실행이다.
- 자산 또는 결과 재사용 정책은 미확인이다.
- 8크레딧 표시는 이 선택 구성의 견적이며 실차감이 아니다.

## 5. 디자인 관찰과 Loretune 제안의 분리

### 관찰

- 어두운 좌측 탐색과 넓은 생성 작업 영역이 보인다.
- 작업 영역 상단에 생성 방식 탭이 나란히 있다.
- 프롬프트, 모델, 출력 옵션이 한 구성 안에 배치됐다.
- 정확한 픽셀·색상값·폰트·점수는 측정하지 않았다.

### Loretune 제안

- 생성 버튼 전 구독 필요 여부와 예상 차감을 선명히 표시한다.
- 접수 불가 상태에는 이유와 가능한 다음 행동을 분리한다.
- 모델·길이·비율 변경이 비용에 미치는 영향을 즉시 갱신한다.
- 이 제안은 경쟁 제품의 관찰 기반이며 Loretune 코드 대조 결과가 아니다.

## 6. 레이아웃·반응형·접근성

- 보존 이미지는 넓은 데스크톱형 가로 화면이다.
- 좌측 사이드바와 중앙 입력 패널의 공존이 관찰됐다.
- 모바일 화면과 반응형 규칙은 미확인이다.
- 키보드 탭 순서, Enter 제출, 포커스 가시성은 미실측이다.
- 화면 판독기 이름, 대비, 오류 안내의 접근성은 측정하지 않았다.
- 한국어 UI와 영어 프롬프트가 함께 있는 사례만 보였고 언어 전환 품질은 미확인이다.

## 7. 무료조건·입출력·시도/접수·실차감

- 무료 표시 잔여: 10 → 10.
- 선택 구성 표시 견적: 8크레딧.
- 업로드: 0건.
- 생성 클릭: 1회.
- 생성 접수: 0건.
- 실차감: 0으로 관찰됐다.
- 구독 게이트 때문에 무료 생성 성립 여부는 확인되지 않았다.
- 공식 FAQ는 생성 영상이 본인에게만 보이며 공유 링크를 공유하면 타인도 열람할 수 있다고 안내한다. 실제 생성 후 공개 동작, 워터마크와 완성 출력 조건은 미검증이다.
