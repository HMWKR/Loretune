# 평가 기준 변경 이력 v1.1 — 작업 맥락을 유지하는 데스크톱

2026-10-26, 최종 평가 전 기록. v1.0의 7축 배점·하위 배점·0–4 앵커·미검증 처리·4개 gate는 유지한다. 이번 문서와 v1.0을 함께 사용한다. **사용자의 새로운 ‘1920 작업 공간은 페이지 전체를 세로로 스크롤하지 않고 핵심 작업을 수행’ 요구로 구성 수용 기준이 변경됐다.** v1.0과 v1.1 결과를 단순 상승·하락으로 비교하지 않는다. 과거 5축/100점과도 비교하지 않는다.

## A2와 A4에 적용할 명시적 수용 조건

조건: 브라우저 **content viewport 1920×1080 CSS px**, 앱 문자배율100%, 실제 DPR 기록. 모니터 물리 해상도1920×1080이라는 뜻이 아니다.

1. 기본 검토, sequence 재생, 정밀 편집 펼침, 긴 검토 패널, 출력 확인에서 `document.scrollingElement.scrollHeight <= clientHeight + 1`이고 가로 문서 overflow가 없어야 한다.
2. 장면 목록, 미리보기와 transport, 현재 대상/시간, 타임라인, 검토 또는 편집의 주요 진입점은 작업 공간 안에 유지한다. 상세 설정·긴 목록은 해당 패널에서만 스크롤할 수 있다.
3. ‘문서 overflow:hidden’만으로는 통과하지 않는다. 숨겨진 필수 내용, 접근 불가한 버튼, 패널의 마지막 입력에 도달하지 못하는 경우 실패다. 패널별 `clientHeight/scrollHeight/overflowY/scrollTop`, 마지막 컨트롤의 rect와 Tab 도달 시 가시성을 확인한다.
4. 정밀 편집을 펼쳐도 현재 미디어·시간 맥락을 보존한다. 패널 내부 스크롤이 필요한 상세와 항상 보이는 요약/transport를 분리한다. 모든 상세 입력을 동시에 화면에 놓는다는 뜻은 아니다.
5. 1280×900은 보조 회귀다. 1920과 동일한 고정 치수나 미디어 면적을 강제하지 않지만 필수 조작은 접근 가능해야 한다.
6. 앱 글자200%, 실제 브라우저 확대, 작은 창에서는 내용 보존을 위해 reflow와 적절한 스크롤을 허용한다. 글자 축소나 clipping으로 ‘무스크롤’을 맞추지 않는다. 앱 배율과 브라우저 확대는 별도 시험이다.

## 중복 감점 방지

문서 스크롤로 미디어가 화면 밖으로 밀리는 구성 문제는 A2에서 한 번 계산한다. 패널 내부 focus가 가려지는 별도 재현 결함이 있으면 F2/H3에 기록한다. 같은 이미지로 두 실패를 추정하지 않는다. 작은 미디어 자체는 A4, 시간좌표 불일치는 E2에만 계산한다.

## 방법론 적용 범위 확장

스크롤 외에 색상·타이포·간격·아이콘·채팅/모델 선택·계획 승인·오류 복구·편집에도 `사용자 과업 → 참고 근거 → 설계 이유 → 구현 위치 → 검증 결과`를 기록한다. 사용자 실험, 경쟁사 동등성, 특정 HEX/px가 업계 정답이라는 주장은 하지 않는다. 기존 정상 상태를 연구를 이유로 다시 구현하지 않는다.
