# 1920×1080 디자인 품질 평가표 v1.0

고정일:2026-10-26. **평가·점수 부여 전 기준 고정.** 주 viewport1920×1080 CSS px, 보조 회귀1280×900. 모바일 추가 작업은 보류한다. 실제 앱 통합·새 미디어 수정 hash는 대기 중이다.

이 표의100점은 아래7축의 전문가 디자인 판단이다. 객관적 경쟁사 서열·제품 완성률·접근성 인증이 아니다. 기존5축/각20점의90과 가중치·범위가 다르므로 점수 상승/하락으로 연결하거나 환산하지 않는다. 동일 조건으로 직접 측정하지 않은 경쟁사의 점수를 만들지 않는다.

## 점수와 커버리지 규칙

- 각 세부항목은0/1/2/3/4의 앵커를 사용하며, 획득점=`세부 배점×앵커/4`이다. 앵커 사이를 임의로 보간하지 않는다. 합계는 마지막에만 소수1자리로 표시한다.
- **0:** 핵심 의미/조작이 깨지거나 해당 품질이 실질적으로 없음. **1:** 중대한 혼동/손실이 반복됨. **2:** 사용할 수 있으나 눈에 띄는 부담/불일치. **3:** 표본 전반에서 명확하고 안정적이며 작은 잔여가 있음. **4:** 정해진 표본에서 반복해 확인됐고 의미 있는 잔여 문제가 없으며 역할에 맞는 세부 완성도가 높음.
- 미검증=`U`, 해당 점수=`null`. 성공으로 점수를 주지 않는다. 미검증을 품질0점 실패로 단정하지도 않는다.
- 커버리지=`평가 가능한 증거가 확보된 세부항목의 최대 배점 합/100`. 시각 캡처만으로 동작 배점까지 커버하지 않는다.
- 커버리지가100% 미만이면 전체 확정 점수는 보류하고 **‘확인된 배점C/100 중 획득P점’**으로 표시한다. P/C를100으로 환산하지 않는다. 미검증 항목이 전체 점수를 얼마나 바꿀 수 있는지도 남긴다.
- 각 항목에 증거 ID, 실제 측정값, 판단, 미확인 조건을 붙인다. 코드 테스트 수·완료 선언·타사 설명만으로 높은 앵커를 부여하지 않는다.
- 같은 결함은 지정된 주 축에서 한 번만 감점한다. 작은 preview→A, 반복 상태→B, 파형/시간 정렬→E, 대비→C, token 관리→G. 다른 축에는 영향만 참조한다. 원인이 같더라도 독립된 사용자 손실을 별도로 감점하려면 구체적 근거와 이유를 밝힌다.
- 기준 변경이 필요하면 새 버전을 만들고 변경 이유를 먼저 공개한다. 결과를 본 뒤 유리하게 가중치를 바꾸지 않는다.

## 점수로 상쇄할 수 없는 gate

상태는 `PASS / FAIL / UNVERIFIED`로만 기록한다. FAIL 또는UNVERIFIED가 있으면 ‘표본 수용 완료/ready’를 선언하지 않는다. 모두PASS여도 제품 전체 readiness를 뜻하지 않는다.

| Gate | 필수 시험 | 실패의 예 |
|---|---|---|
| H1 실제 media/seek/sync | 현재 자료 재생, source trim·edited time 변환, 로딩 중seek, 전환 후 오래된event, 비교시이전sequence audio/loop정지 | 표시한대상과실제frame불일치,다른음악잔존,막힌재생을진행으로표시 |
| H2 승인·비용·버전 무결성 | audition/비교 전후선택·승인·timeline불변,모델/예상비용/승인범위,저장/미확정·복구표현 | 비교가사용확정으로바뀜,승인되지않은입력이출력된것처럼표시 |

| H4 필수대비 | 실제문자/상태식별/focus/input경계의적용배경쌍;필요시alpha합성 | 필수문자/상태식별단서가필요대비에미달 |

H2의 backend 전체 보안·결제 검증은 이 디자인 평가 범위를 넘어선다. 디자인 관련 표시·상태 무결성의 표본과 기능팀 회귀를 구분한다. H4는 WCAG 전체 인증이 아니다. inactive/장식경계는 적절한 예외로 분리한다.

## 증거 등급과 기록 형식

- `M`: 이 검토에서 측정한DOM/computed/시간/해시.
- `O`: 이 검토에서 실제 수행한 UI/keyboard와 저장 후 열어본 픽셀.
- `S`: 기능팀/연구팀이 제공한 근거. 제공자·버전 명시.
- `R`: 경쟁사 capture/공식 설명. 우리 앱 실제동작의 증거가 아님.
- `P`: 제안·가설. 점수 근거로 사용하지 않음.
- `U`: 미확인. 점수null.

항목별 행: `ID | 배점 | 앵커 | 획득점 | 근거등급/파일 | 실제값 | 판단 이유 | 반례·한계`. 결함은 `원인 → 사용자영향 → 재현/측정 → 수정 제안 → 재검증 조건`으로 적는다.

최종 전달에는7축 결과,평가커버리지,4gate,검증한revision/viewport/fixture,누락표본을 함께 표시한다. competing products의순위/점수는 이 표에 포함하지 않는다.
