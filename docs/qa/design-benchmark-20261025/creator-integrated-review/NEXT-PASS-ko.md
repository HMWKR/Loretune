# 다음 bounded 개선: 선택 장면의 제작 상태 카드 통합

현재 실행본은 수정하지 않는다. 새 backend/실제 공급자 활성화는 범위 밖이다.

## 재현 근거

`QA 통합 제작 20261025`에 `fal-flux-schnell`이 저장돼 있는데 모델 설정은 선택된 모델을, 이미지 패널은 ‘이미지 모델 미선택’을 표시한다. [모델 설정](06-actual-model-selection-1280.png), [이미지 패널](07-actual-image-status-1280.png), `populated-observations.json`으로 재현했다. 선택과 실행 준비가 서로 다른 상태라는 사실을 사용자가 내부 구현으로 해석해야 한다.

## 한 카드로 표현할 계약

현재 `이미지 모델·기존 결과`와 `영상 생성`을 **장면 제작**이라는 한 맥락으로 묶는다. backend 경로의 수만큼 사용자용 메뉴를 만들지 않는다.

1. **선택 모델**: 저장된 model_settings 기준 이미지·영상의 정확한 제품명. 전체 모델 식별자는 ‘모델 정보’에 제공하며 값을 바꾸지 않는다.
2. **실행 준비**: 미선택, 선택됨·연결 미검증, 사용 차단, 승인 범위 내 사용 가능을 구분. authoritative server capability만 사용하며 선택 저장을 활성화로 해석하지 않는다.
3. **현재 가능한 다음 행동**: 기존 이미지·영상 연결/모델 선택 확인/이미 존재하는 결과 확인. 지원하지 않는 새 fal recovery·승인·생성 버튼은 만들지 않는다.
4. **이미 접수된 작업**: 모델 선택 변경과 무관하게 그 작업의 원래 모델·실제 상태로 표시. 요청 ID/adapter/legacy 용어는 작업 기록에만 둔다.
5. 테스트 미디어 만들기는 명시적인 테스트 도구 disclosure로 보존. 테스트 결과의 badge·provenance는 유지한다.

예시: `이미지 / FLUX Schnell / 선택됨 · 연결 확인 필요 / 지금은 기존 이미지를 연결할 수 있습니다. / 모델 선택 확인`. 미선택은 저장된 role 선택이 없을 때만 사용한다. registry와 legacy capability가 다른 모델을 가리키면 둘을 합쳐 준비 완료로 표시하지 않는다.

## 디자인 경계

현재3열·미리보기736×324·timeline 배치를 유지한다. 오른쪽254px 안에서 제목18/본문14/상태12 scale과 조용한 tonal surface를 사용한다. 항목마다 같은 검정 outline card를 중첩하지 않는다. 변경할 값과 다음 행동만 control로 보이며 기록은 한 disclosure로 모은다. 모바일 identity strip과 검토 action을 제작 설정으로 밀어내지 않는다. Clipchamp media 우선 구성과 ElevenLabs 선택 맥락 조작 원칙을 따르며 새 palette/장식/브랜딩은 추가하지 않는다.

## Acceptance

- 저장된 FLUX 선택과 연결 미검증이 동시에 정확히 보인다. 미선택이라고 말하지 않는다.
- 선택 없음/미검증/차단/실제 capability available 네 경우 검사. 검증 없이 실행 활성화 금지.
- 기존 job 모델·상태가 현재 선택과 섞이지 않음. 진단 원문은 접근 가능.
- 사람 승인·가격·전송 범위·사용권·test badge·draft/F07/focus·기존 recovery handler 보존.
-390px에서 맥락·핵심 다음 action이 같은 화면 안에 있고 수평 overflow 없음.
- 동일 viewport/프로젝트에서 통합 후 캡처. 자동 점수 가산 없음.

이 한 pass가90을 보장하지 않는다. 계획 form 밀도와 전체 control의 시각 완성도도 남지만, 이번에는 실제 모델 상태 모순과 그 내부 경로 노출을 먼저 해결한다.
