### 원문과 보충 관계

[사업 chapter](../specification/IP_Music_Video_Platform/chapters/01_business.md) L7, [Master](../../Master_Specification.md) L125, [원본 DOCX](../specification/IP_Music_Video_Platform/output/01_Business_Plan_and_Validation.docx)의 `word/document.xml` 본문 직접 자식 문단82에는 **“Aethon과 별개의 신규 사업”**이라는 작성 당시 표현이 있다. 문단82는 페이지82가 아니다. 해당 원문은 보존한다.

현재 해석: **Aethon은 IP 음악영상 제작 제품이며 AethonSaaS 플랫폼과 별개 프로젝트다.** AethonSaaS의 기능은 목적 적합성을 검토한 개별 계약만 채택한다. 과거 고객·유료 의향·인력·제휴·데이터·성과·가격의 승계를 뜻하지 않는다. 원문의 검증 전 가정 및 성과 증거 요구도 유지한다. 법인·IP 소유·라이선스 이전을 확인한 법적 판단이 아니다.

이전 설명의 ‘팀 협업 OS’를 모든 사용자의 필수 경로로 해석하지 않는다. 실제 [피벗 사업계획 §1.1–1.2](../specification/IP_Music_Video_Platform/chapters/01_business.md)는 소규모 레이블·운영팀을 초기 가설로 좁히면서도 **개인 VTuber(구매자·사용자·승인자가 겹침)**를 고객군에 포함한다. 따라서 개인 사용을 새 고객 성과로 발명하거나 기존 계획에 없던 것으로 기술하지 않는다. 최신 사용자 결정은 제품 경로에서 **팀을 필수 진입 조건으로 두지 않는 것**이다. 역사적 협업·승인 조율 사용례는 유지하고 시장 수치·고객 성과·초기 ICP·가격을 임의 수정하지 않는다. 그런 사업 가정의 별도 개정은 새로운 근거와 결정이 필요하다.

## 3. 개인 기본·협업 선택의 기능 경계

**개인 기본 경로:** 작품 생성/열기 → 자료·모델 선택 → 대화·계획 → 권리·비용·실행 범위 확인 → 실행/복구 → 후보 검토·부분 편집 → 승인된 버전 출력·재개. 팀 생성, 초대, 공유, 타인의 팀 승인이 선행 조건이 되어서는 안 된다. 사용자는 자신의 권한 안에서 사람 승인·실행 결정을 직접 한다. 이 문장은 모든 로컬 사용자가 관리자 권한을 갖는다는 뜻이 아니다.

개인에게도 비파괴 버전, 정확한 자료 역할·개정, 독립 대화, 선택 모델, 비용/한도, 진행/unknown/실패 구분, 초안 보존·기존 요청 복구, 권리 및 실행 범위 검사가 필요하다. ‘협업 선택’을 안전 검사의 선택 적용으로 해석하지 않는다.

**협업 확장 경로:** 사용자가 명시적으로 특정 버전의 후보·입력 범위를 공유 → 권한 있는 상대가 열람/재사용 → 새 초안·새 실행 승인 → 비교·채택 → 해당 권한의 승인/출력. 열람, 입력 재사용, 실행, 채택, 공식 설정/출력 승인은 서로 다른 권한이며 공유만으로 승격되지 않는다. 실제 인증·서버 ACL·파일/검색/캐시 접근 및 철회, 공유 대상 버전·동시성 검사가 준비되기 전 팀 기능 완료로 표시하지 않는다. 구체 역할 이름과 관리자 정책은 구현 전 결정 대상이다.

개인 AD04 ‘이어서 만들기’와 AD05 ‘의견을 변경안에 사용’은 **AD03 팀 기능을 기다리지 않는다**. 자신의 허용된 정확한 버전에서 새 초안을 만들며 원본·기존 승인·실행을 보존한다. 타인 자료·댓글의 팀 변형에만 AD03 권한 기반이 추가로 필요하다.

## 4. 원본07과의 관계

[원본07](../../07_Chat_Directed_Multimodel_Production_Spec.md)의 독립 chat/image/video 선택, 선택 chat→서버 도구→fal image/video, no-MCP 제품 경계, 온톨로지·출처, 비용·권리·사람 승인·복구는 유지한다. 개발용 연구 도구와 제품 호출 구조는 별개다.

원본의 조직 정책·역할·교차조직 접근·BYOK 조건은 해당 기능의 수용조건으로 계속 추적한다. 개인 기본 경로가 팀 가입을 요구하지 않는다는 결정은 조직 기능의 요구를 삭제하거나 운영 인증이 구현됐다는 뜻이 아니다. 개인 actor/소유권을 기존 계약에 어떻게 매핑할지는 구현 전 설계하고, UI만 개인 모드로 숨긴 뒤 서버 검사를 생략하지 않는다. 원본38AT의 미실시 조건은 그대로 남긴다.
