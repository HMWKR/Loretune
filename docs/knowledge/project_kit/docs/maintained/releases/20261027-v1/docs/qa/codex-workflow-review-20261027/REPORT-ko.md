# Aethon 플랫폼 제작·디자인 검증 — 2026-10-27

상태: **부분 구현·제한된 검증. 실무용 제품 완성 아님.** 사용자 요청에 따라 실제 AI 영상 생성 모델 시험은 플랫폼의 실무 워크플로가 준비될 때까지 보류한다. 이 작업은 합성 데이터와 Claude 채팅 모델을 사용했으며 외부 AI 영상 생성 호출은 0회다.

## 후속 작업에 유지할 사용자 지시 — 2026-10-27

- **기본 과업:** 개인 사용자는 음원부터 넣고 사진을 추가하거나 음원만으로 시작할 수 있어야 한다. 팀 생성·공유는 개인 작업의 선행조건이 아니다. 기존 미디어가 없더라도 플랫폼 내부의 텍스트·도형·모션과 편집으로 결과를 만들 수 있는 경로를 확인한다.
- **워크플로와 디자인:** 사용자 과업을 따라 중복 단계·입력을 찾아 필요한 경우 병합하고, 당장 결정에 필요하지 않은 내부 ID·진단은 기본 화면에서 줄인다. 모델 선택과 실제 실행 범위, 비용·권리·승인·오류·복구에 필요한 정보는 필요한 시점에 남긴다. 관찰과 사용자 혼란 가설을 분리한다. 기능 작업 뒤 Hallmark·Impeccable과 기존 참조·토큰을 활용해 문제→대안→계획→구현→동일 조건 검증을 수행한다. 상세 방법의 선택과 근거는 [방법론 표의 최신 보강](../design-system-redesign-20261026/METHODOLOGY-FIT-MATRIX-ko.md)을 따른다.
- **AI와 편집:** 채팅에서 선택한 모델이 실제 플랫폼 도구와 편집 방식을 이용해 제안·수정·결과 확인까지 수행하는지 검증한다. 모델의 설명과 서버가 실제 저장·승인·렌더한 사실을 구분하고, 모델이 모든 도구를 완벽히 이해한다고 가정하지 않는다. Claude 시험 결과와 일반 사용자용 연결의 구현 여부는 별도로 기록한다.
- **검증 순서:** 버튼 존재나 오류 부재가 아니라 음원 입력→계획→제작→검토→편집→출력→재개를 실제 사용자가 수행할 수 있는 수준으로 검증한다. 실제 AI 영상 생성 모델 시험은 이 플랫폼 워크플로가 실무 수준으로 구현·검증된 뒤 진행한다. 현재 합성 fixture 또는 로컬 렌더만으로 실무·공급자 준비가 완료됐다고 표시하지 않는다.
- **온톨로지:** 프로젝트 요구·문서·결정·테스트의 온톨로지와 제품의 IP·자산 온톨로지를 구분하고 둘 다 영향·연결·미완료를 점검한다. 최근 문서의 등록·분류·생성문맥과 검증 영수증을 실제로 확인하기 전까지 문서 게이트 통과로 간주하지 않는다.
- **누락 방지:** 원본 수용항목, 최신 사용자 결정, 현재 구현 및 실제 결과를 대조하고 구현·부분 구현·미검증·외부 권한 의존·명시적 보류를 구분한다. 관련 정상·실패·경계와 재접속을 확인하고, 전체 완료나 누락 없음은 남은 항목과 증거를 설명할 수 있을 때만 주장한다.
- **방법론·오픈소스:** 하나의 프레임워크를 강제하지 않는다. 공식 자료와 기존 기록을 활용하고, 공개 GitHub 코드는 문제 적합성·라이선스·의존성·유지보수·데이터 처리·기존 구조 영향을 확인한 뒤 필요할 때만 도입한다. 출처가 공개됐다는 사실과 실제 오픈소스 라이선스·제품 통합 검증은 구분한다.
- **REA와 GitHub의 병행:** REA 분석이 성공해도 관련 공개 GitHub 구현을 별도로 찾아 플랫폼에 유용한지 평가한다. REA 접근이 불가능하면 그 차단 사실을 남기고 공개 자료·공식 문서 조사를 계속한다. 가져올 만한 부분은 라이선스와 의존성을 확인하고 플랫폼의 음원 우선 흐름, 사용자에게 필요한 정보, 기존 저장·승인·편집 구조에 맞게 변형한 뒤 실제 작동을 검증한다. REA 분석·공개 코드 조사·제품 통합은 각각 독립된 증거다.
- **승인 및 보존:** 권한이 필요한 외부 서비스·운영 데이터·비용·배포 등의 작업은 별도로 남기고, 그 외 승인된 작업을 계속 진행한다. 기존 파일·데이터와 다른 작업자의 변경을 보존하며 모호하거나 검증하지 않은 내용을 임의로 완료 처리하지 않는다.

### 다음 세션의 작업 순서와 완료 판정

1. 최신 사용자 지시 → 현행 프로젝트 문서·온톨로지 → 현재 코드·실제 실행 증거 순으로 대조하고, 이전 조사 중 현재 상태에 유효한 부분은 재사용한다. 제품 온톨로지의 데이터와 프로젝트 지식 registry는 별도로 확인한다.
2. 사용자 과업의 정상·빈 상태·오류·취소·복구와 음원 단독/사진 추가 경로를 확인해 남은 요구·누락을 추적한다. 관찰, 추론, 미확인을 구분하고 원본 요구와 새 지시가 충돌하면 기록한다.
3. `$karpathy-guidelines`에 따라 필요한 최소 변경과 검증 기준을 정한다. 의미 있는 기능·UI 변경은 기존 동작을 보존하면서 실제 요청·화면·저장 결과와 실패·경계를 검사한다. 실행한 스킬, 명령, 독립 검토, 수동 관찰을 구분한다.
4. 기능 작업 후 `$hallmark`와 `$impeccable`의 실제 설치본 및 프로젝트 디자인 기준을 확인하고, 증거 기반 문제·대안·범위와 검증 계획을 사용자에게 알린 후 구현한다. 허용된 범위의 단계마다 반복 승인을 요구하지 않는다. 1920×1080 우선, 1280×900 보조와 동일 데이터·상태 비교를 기본으로 한다.
5. 실제 모델·실제 사용자·접근성 보조기술·유료 공급자·배포는 각각 별도의 증거 상태를 갖는다. 사용자가 보류한 실제 AI 영상 모델 시험은 실무 워크플로 준비 이후에만 진행한다.
6. 남은 요구와 수용 기준의 구현·검증 근거를 연결해 설명할 수 있을 때만 완료로 표시한다. 외부 권한이나 필수 정보가 없으면 해당 부분을 분리해 이유와 다음 행동을 기록하며 나머지 승인된 작업은 계속한다. 문서 게이트의 등록·분류·문맥 불일치는 통과로 바꾸지 않는다.
7. 경쟁 서비스의 실제 화면이나 배포 산출물이 근거로 필요할 때는 대상과 질문을 지정하고 REA MCP·허용된 브라우저 도구의 실제 가용성과 범위를 확인한다. 기존 참고 근거를 먼저 재사용하고 관찰·추론·미확인과 라이선스/출처를 분리한다. 공개 구현이나 경쟁사 패턴을 그대로 복제하지 않고 Aethon의 사용자 과업·브랜드·기존 권리/승인·구조에 맞게 재설계하고 실제 동작을 검증한다.
8. 작업 완료 전, 사용자가 다시 묻기 전에 요구·작업·누락과 증거를 점검해 남은 항목 및 다음 실행 범위를 보여 주고 사용자 허락을 받은 뒤 그 다음 단계로 진행한다. 이미 시작한 작업을 안전하게 검증·기록하고 검토 가능한 결과를 준비하는 과정과 후속 작업 진행 승인을 구분한다.
9. 제품 완료 판정은 코드·단위 테스트·디자인 화면이 아니라 실제 시스템과 사용자가 끝까지 수행할 수 있는 업무에 둔다. 기능별 정상/실패/경계에서 화면 조작→서버 응답→실제 저장·재조회→관련 결과를 확인하고, 별도로 음원만/음원+사진의 전체 생성·검토·편집·출력·재개를 연결해 시험한다. 미디어·오디오·자막의 결과 재생과 동기화, 중단·복구·재접속, 모델/도구가 같은 편집 상태를 다루는지, 실행 환경의 권한·데이터·비용·성능을 해당 범위에서 확인한다. fixture·로컬 시험·실제 모델/운영 환경·실사용자 결과를 서로 대체하지 않는다. 검증할 수 없는 기능은 이유와 다음 행동을 남기고 완료로 계산하지 않는다.

### 현재 누락 점검과 검증 — 진행 확인 대기

| 구분 | 현재 확인 또는 남은 작업 |
|---|---|
| 복수 대화 | 선택·생성·모델 선택·대화별 초안과 계획을 격리 브라우저에서 일부 확인했다. [화면 표본](session-ui-1280.png)은 검증 당시의 합성 자료다. 지연 전환 차단도 표본 확인했으나 두 탭 병행, 키보드 선택, CS01–18 전체 및 응답 완료 후 모델 변경 예약은 미완료다. |
| 대화 격리 | 미승인 Take·참고·제안 카드·모델 인계·모션 프레임과 생성 준비에 대한 추가 누출 경로를 수정했다. 격리 HTTP와 계약 fake로 소속/승인/철회, 제출 직전 철회 차단을 확인했다. 소속 정보가 저장되지 않은 과거 생성 준비의 실제 대화 출처는 복원할 수 없다. 이는 팀 인증 검증이 아니다. |
| 음원·자체 모션 | 합성 음원의 브라우저 등록과 새로고침 복원, 선택 사진 등록·Take 선택을 확인했다. 사진·모델 연결 없이 직접 텍스트 모션의 빈 입력 차단→저장→승인→로컬 렌더→Take를 확인했고 [한글 프레임](manual-motion-frame.png)을 열어 봤다. 전체 음원→최종 영상 출력·재개와 실제 사용자 평가는 남았다. |
| 디자인 | [음원 빈 상태](current-audio-empty-1920.png)와 [크기 초과 오류](current-audio-oversize-1280.png)를 확인했다. 상한 사전 안내 부족과 입력에서 떨어진 오류 위치는 후속 개선 대상이다. 새 모션 화면의 프레임·좌표 등 상세 입력을 필요한 경우에만 보여 줄 방안도 필요하다. Hallmark 정적 검사와 Impeccable 검출은 실행했으나 Hallmark render tier는 `puppeteer-core` 부재로 미실행; 전체 디자인/접근성 통과는 아니다. |
| 일반 AI·편집 | 기본 일반 Claude 연결은 여전히 제한된다. 선택 모델의 일반 브라우저 대화→실제 편집→출력, 실무 사용자의 검증, 자막 번인·자동 전사·고급 편집 등은 별도 확인/구현이 필요하다. 실제 AI 영상 모델 시험은 사용자가 요청한 준비 조건 이후로 보류한다. |
| Blender·3D | [모델화 계획](../../design/AI-MODELING-PLAN.md)에 플랫폼 내부의 선택형 3D 구도·조명·카메라와 채팅/직접 편집 방향이 기록돼 있지만 구현·실행 시험은 아직 없다. 설치된 Blender 5.2.2 LTS의 실행 파일을 REA로 열어 Mach-O 요약까지 확인했다. 이 분석은 렌더·3D 기능·플랫폼 연결 검증이 아니다. 사용자가 말씀한 Blender와 REA 결합의 정확한 이전 원문·추가 범위는 기존 계획에서 확인되지 않아 사용자에게 확인을 요청했다. |
| 프로젝트/제품 온톨로지·문서 | 프로젝트 registry의 관계 조회 및 제품 설정 제안·승인 일부를 시험했다. 요구 전체와 문서의 등록·생성문맥·receipt 정합성은 미완료다. 문서 게이트는 blocked이며 누락 등록·문맥 재검토·미분류 항목을 통과로 표시하지 않는다. |
| 이전 외부 차단 재검토 | REA는 공개 웹과 Blender 파일의 제한된 분석을 직접 수행했으나, 과거에 자동 승인 심사에서 거절된 별도 Codex 추론 실행이 성공했다는 뜻이 아니다. 당시 거절 이유는 실효 외부 provider/base endpoint와 수신자를 확인하지 못한 것이었다. Library의 이전 `prepare_uploads`와 동일한 기능은 현재 도구 목록에서 확인되지 않아 최신 전달 성공을 주장할 수 없다. |
| 전체 회귀 | 현재 코드에서 `python3 -m unittest discover -s tests -q`: 428개 통과. 테스트 HTTPError 정리 관련 ResourceWarning 3건이 남았다. 자동 테스트 결과는 실사용·실제 공급자·전체 수용의 대체가 아니다. |

다음 단계는 위 미완료 항목의 우선순위와 사용자가 요청한 진행 허락을 받은 뒤 이어간다. 추가 비용·계정·운영 환경 접근은 각각 현재 승인과 별도 검증 범위를 따른다.

## 구현 및 검증

- 복수 대화 partial에서 기존 도구 인계 예외, 기본 대화 이력 호환, 미디어 경로의 대상 객체 혼동, 같은 도구 호출 재생 결과 차이 및 다른 작품 생성 때 소스 세션이 바뀌는 회귀를 수정했다. 이름 없는 기존 독립 도구 입력은 기본 호환 범위로 처리한다. 격리 HTTP에서 동일 도구 호출을 두 번 보내 결과 일치·계획 한 개를 확인했다.
- `unittest discover` 417개 통과: [실행 로그](regression.log). 이후 추가한 세션 격리·재열기·stale 거절·서로 다른 세션 쓰기 검사는 3개 별도 통과. 이 검사가 CS01–18 전체 수용을 대신하지 않는다.
- 첫 작품이 없을 때 작품 만들기 행동을 전면에 두고 불필요한 음원 입력을 숨겼다. 생성 후 음원 입력 복원·새로고침 후 선택 유지·Enter로 dialog 열기를 격리 브라우저에서 확인했다. [1920](empty-1920.png), [1280](empty-1280.png) 실제 화면을 열어 확인했다. 전체 화면 디자인·키보드·스크린리더·확대 검증은 아니다.

## 실제 Claude와 플랫폼의 합성 제작 표본

Claude Haiku 5.5를 합성 프로젝트에 제한해 3개 논리 과업, 각 3 Messages로 실행했다. 입력은 합성이고 AI 영상 생성 모델은 사용하지 않았다. usage 가격 합계 **$0.010185**, 청구서 금액은 미확인이다. 실행 controller가 사람 역할의 검토·승인을 수행했고 브라우저 채팅에서 모델을 호출한 것은 아니다.

1. [모션 원본](claude-motion-v1.mp4): Claude가 제목 `새로운 리듬`, 사각형, 원과 키프레임을 제안했고 플랫폼이 검증·승인 후 후보 Take로 등록했다. 1920×1080, 24fps, 4초 H.264. [모델 결과](case-1-turn.json).
2. [모션 수정](claude-motion-v2.mp4): 원의 표시 구간과 키프레임만 12프레임 지연하는 제안을 원본과 구조 비교했고 다른 데이터가 같음을 확인했다. 새 검토 후 두 번째 Take로 출력했다. [모델 결과](case-2-turn.json). 응답의 “앞선 기준 리비전 0이 잘못”이라는 자기 정정은 당시 최초 제안이 실제로 기준 0이었던 점과 맞지 않아 설명 오류로 남긴다.
3. [편집 출력](edited-output.mp4): Claude가 서버 문맥 조회 뒤 세 클립 3→1→2, 자막 세 구간, 기존 음원 1초 오프셋을 제안했다. 구조를 비교하고 승인·적용 후 3초 1920×1080 H.264/AAC 출력이 완료됐다. [자막 SRT](edited-output.srt)는 별도 파일이다. [모델 결과](case-3-turn.json). 출력의 전체 재생·청취 및 실제 사용자 평가는 수행하지 않았다.

이는 특정 합성 지시에서 플랫폼 도구를 조회·제안·적용한 결과다. 모델의 일반적 이해나 완벽한 편집, 전체 도구·모든 모델, 브라우저에서 일반 사용자의 Claude 연결, 전문 타이포그래피 품질, 다중 사용자 보안, 운영 준비를 증명하지 않는다. 현재 모션의 종류·길이·폰트·애니메이션 범위는 제한돼 있다.

## 프로젝트 온톨로지 적용

사용자가 지정한 온톨로지는 제품의 IP 기억 그래프가 아니라 개발 프로젝트의 문서·요구·결정·화면·API·시험·근거를 연결하는 지식 registry다. 두 프로젝트 키트에 대해 `kb.py status` 및 `validate`를 실행했고 각각 revision 9, 1,772 객체, 검증 이슈 0이었다. 이 검사는 등록부 구조·해시 범위에 한정된다. 사용자 최신 지시와 미등록된 현행 보충문을 별도로 대조해야 한다.

모델 인계 `MS-FR-11`의 `impact`는 `MS-AT18`, `MS-AT19` 두 시험을 반환했다. 해당 [작업 문맥](../../knowledge/project_kit/generated/context/codex-workflow-20261027-technical.md)은 세 객체를 선택하고 누락 0으로 생성됐으며 `context-check`는 유효했다. 편집 요구 `FR-055`의 `impact`는 선언된 영향 항목 36개를 반환했으며 원본 보존, 미리보기와 출력 일치, 가사·타이포그래피와 음원 동기화 등 후속 검증을 포함한다. 영향 조회는 선언된 관계만 반영한다.

등록부의 편집 승인·요구 채택·검증 상태는 서로 다르다. 최근 유지 문서 및 본 보고서의 등록·분류·receipt 갱신은 아직 완료되지 않았고 이를 자동 승격하지 않았다. 이후 작업은 관련 head와 최신 사용자 지시를 대조하고 관련 impact·문맥·receipt를 확인한 뒤 구현과 실제 결과를 별도 기록한다.
