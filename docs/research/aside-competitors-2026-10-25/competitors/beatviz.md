# BeatViz 개별 경쟁사 보고서
## 조사 기준
- 작성일: 2026-10-25.
- 범위: 기존 공개 UI 관찰, 최신 build-context, 승인 테스트 체크포인트.
- 새 브라우저 탐색, 생성, 설정 변경은 하지 않았다.
- 제품 소개·UI 표식·실제 실행 결과를 구분한다.
- 완성 생성, 렌더 완료, 결과 품질 검증은 0건이다.
## 최종 결론
- BeatViz는 음악 업로드와 프롬프트를 결합한 AI 음악 영상 제작 흐름을 제시한다.
- Chat, Workflow, Editor 및 별도 Custom Video Gen 도구를 IA에 둔다.
- 승인 관찰에서 Free 150 크레딧과 Custom Video Gen의 Veo 3.1 조건이 보였다.
- 다만 이 Custom Video Gen 경로가 음악 MV 경로와 같은 견적·결과 조건이라는 근거는 없다.
- 결과의 공개 기본값을 확인하지 못해 생성하지 않았다.
- 따라서 무료 생성 가능성, 실제 차감, 품질, 렌더 성공은 미검증이다.
## IA와 메뉴
- 좌측에는 Home이 있다.
- BeatViz Suite 아래 Chat, Workflow, Editor가 있다.
- Explore 아래 Showcase, My Creations가 있다.
- Tools 아래 Custom Video Gen이 있다.
- Music Gen, Music Analyzer도 보인다.
- Start/End Frame Generator도 보인다.
- 상단에는 Help, Pricing, Discord, 언어 선택, Get Started가 있다.
- 이 메뉴 구조는 캡처 시점 UI의 정보 구조다.
- My Creations가 존재해도 개인 작업을 열어 보지 않았다.
## 제작 동선: 입력 → 작업 → 결과
- Chat 화면은 Add Music을 첫 입력 행동으로 제시한다.
- 음악 영상 설명 입력은 선택 사항으로 표시된다.
- 모델 선택에는 BeatViz 2.0 표식이 보인다.
- Character 선택이 보인다.
- Mode는 Standard로 보인다.
- 화면비는 16:9가 보인다.
- 해상도는 720p가 보인다.
- 공개 범위 드롭다운에는 Public이 표시된다.
- 음악이 없는 상태에서 Start Creating은 비활성이다.
- 공개 설명은 BPM·리듬 분석, 장면 생성, beat-sync를 말한다.
- 실제 음악 분석, 프롬프트 반영, 생성 작업 접수는 실행하지 않았다.
- 결과 영상과 편집기는 검증하지 않았다.
## 상태·오류·수정·재사용
- 음악 미첨부 상태의 비활성 CTA는 입력 선행 조건을 보여 준다.
- 생성 후 진행 상태나 오류 상태는 확인하지 못했다.
- 실패 시 재시도, 환불, 크레딧 반환은 미검증이다.
- Workflow·Editor 메뉴가 있어도 실제 수정·타임라인 동작은 검증하지 않았다.
- Character Presets, 스타일 조합, 시작/끝 프레임, seed의 UI 존재가 기록됐다.
- 이 옵션들이 결과를 재현하거나 재사용하게 하는지 실행으로 확인하지 않았다.
- Storyboard, Keyframe Previews, Material Library 진입 카드는 별도 관찰됐다.
- 각 카드의 실제 편집·저장 동작은 미확인이다.

## 디자인 관찰

- 스크린샷은 검은 상단 바와 어두운 좌측 사이드바를 사용한다.
- 밝은 연두색이 Chat 선택 상태, 라벨, CTA에 반복된다.
- 본문은 흐릿한 자연 이미지 배경 위에 반투명한 입력 패널을 둔다.
- 입력은 Add Music 버튼, 대형 설명 영역, 옵션 칩처럼 계층화된다.
- Public 범위 선택과 Start Creating이 같은 하단 행에 배치된다.
- 사이드바는 섹션 제목과 아이콘을 사용해 많은 기능을 나눈다.
- 이는 화면 시각 관찰이며 정확한 색·여백·폰트 값은 측정하지 않았다.

## 제품에 적용할 제안

- 음악 입력 전 비활성 CTA와 이유를 함께 보여 주는 패턴을 검토할 수 있다.
- 모델·비율·해상도·공개 범위처럼 결과에 영향을 주는 설정을 생성 직전에 모으는 방식은 참고할 만하다.
- 단, 공개 기본값은 선택값처럼 보이는 UI만으로 확정하지 말고 실제 저장·출력 시점까지 검증해야 한다.
- 도구군이 많으면 작업 목표별 진입 차이를 간단히 안내해야 탐색 부담을 줄일 수 있다.
- Music Analyzer와 영상 생성의 결과 연결은 사용자가 이해할 수 있게 명시하는 편이 좋다.
- 이 제안은 Loretune 코드 대조 없이 작성한 관찰 기반 제안이다.

## 레이아웃·반응형·접근성

- 스크린샷 파일은 2880×1800 픽셀이다.
- 파일 픽셀은 CSS 뷰포트나 반응형 중단점이 아니다.
- 캡처에는 좌측 고정형으로 보이는 사이드바와 넓은 작업 영역이 보인다.
- 모바일 구성은 관찰하지 않았다.
- 키보드 순서, 포커스 표시, 스크린리더 이름은 검증하지 않았다.
- 텍스트 대비와 클릭 대상 크기도 수치로 측정하지 않았다.
- 따라서 접근성 및 반응형 완성도를 단정하지 않는다.

## 무료 조건·입출력·실차감·시도·접수

- Free Plan 잔여는 150 → 150으로 관찰됐다.
- Custom Video Gen에는 Veo 3.1, 8초, 720p, 35크레딧 표시가 있었다.
- 이 수치는 Custom Video Gen 경로의 표시 견적이다.
- Standard Fast 8초의 35–45/segment 범위와 동일시하지 않는다.
- 음악 MV 생성 경로의 실제 견적은 확정하지 못했다.
- 입력 업로드 0건, 생성 시도 0회, 접수 0회다.
- 공개 기본값·비공개 동작을 확인하지 못해 생성하지 않았다.
- 확인된 렌더 완료는 0건이다.
- 실차감, 워터마크, 출력 품질은 모두 미검증이다.

## 공개 범위 해석의 한계

- 승인 스크린샷의 생성 패널에는 Public 표시가 보인다.
- 해당 드롭다운의 선택 가능 옵션과 계정별 기본값은 이 문서 범위에서 검증하지 않았다.
- 저장 후 결과가 실제로 공개되는지, 공개 선택을 바꿀 수 있는지도 미검증이다.
- 그러므로 Public 텍스트만으로 공개 정책이나 기본값을 단정하지 않는다.
- 체크포인트의 차단 사유는 결과 공개 기본값 미확인이다.

- 이 문서는 기존 공개 UI 및 체크포인트 기록에 근거한다.

- Neural Frames REA 분석의 cleanup_incomplete 이후 추가 REA 분석은 중단됐다.
- 일반 브라우저 UI 관찰을 REA 증거로 바꾸어 기록하지 않는다.
- 공개 JS 표식은 전체 구현, 서버 처리, 모델 동작을 증명하지 않는다.
- Loretune 코드·DB·서버 대조는 OS 접근 거절로 수행하지 못했다.

## 채택할 점·피할 점

- 채택 후보: 입력 의존성을 비활성 CTA로 드러내는 방식.
- 채택 후보: 음악·모델·비율·해상도·공개 범위를 한 패널에 모으는 구조.
- 피할 점: 서로 다른 도구 경로의 견적을 단일 비용으로 비교하는 분석.
- 피할 점: Public 표식만으로 실제 공개·비공개 집행을 확정하는 판단.
- 피할 점: 다기능 사이드바를 사용자 목표별 안내 없이 그대로 확장하는 설계.
- 최종 판정: 편집 도구 구조는 참고 가능하나 무료 조건과 생성 결과는 미검증이다.
